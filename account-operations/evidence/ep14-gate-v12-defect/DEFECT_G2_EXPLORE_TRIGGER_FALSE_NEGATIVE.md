# 缺陷 G-2 · 探索触发漏检：闸门在它最该起作用的那一格没有响

## 1. 现场

`account-operations/evidence/ep08-module-ab-v12/FX-M3-HOLD-03__B.json`

候选臂在留出场景 03 上的输出里有这么两句：

```text
L10  核心命题是：在数据回来之前，用不承诺换取可信，用试穿实拍让观众看到真实上身效果。
L13  这条内容发布后要盯的：门店和企业微信预约是否增加、私信里面料疑问是否被接住；观察窗口至少一周。
```

这在产品语义上就是一次**受控探索提案**：一个主要命题 + 一个最小可逆动作 + 观察项 + 观察窗。
按 `SKILL.md` O-5 与〈必填项闸门〉，它应当触发探索六项。

**闸门判定：**

```text
gate_status              CLEAN
triggers_effective       explore = False
positive_hit(explore)    None
取稿路径                  draft_verbatim（原稿逐字返回，未进补齐）
```

**三名互不通气的盲评者独立给出同一结论**（他们看不到闸门，也不知道这是候选）：

> 「有主要假设、最小可逆动作和粗略到期条件，**但没有任何反证条件**——没写什么结果算这个角度不成立、以及不成立后怎么办。」
> 「给了观察项和『至少一周』的窗口，但没有反证条件也没有到期后的处置动作，『至少一周』是开口窗口不是到期条件。」

`[探索·推翻信号]` 与 `[探索·到期或复验]` 这两项**正是第 3 轮实测漏写、并因此催生整个闸门的那两项**。
闸门建起来之后，在留出集上它们又一次被漏写，而**闸门没有响**。

这一格直接构成 `M3-AC-18` 判 `FAIL(INSUFFICIENT)` 的那一维（实验设计 = A 优且实质）。

## 2. 根因，以及我在方法上漏了哪一半

`explore` 触发只能靠自报 + 正文措辞。为了压掉第 4 轮实测出的大量误报
（无极性关键词匹配 67/70 全是误报），v1.2 把命中条件收紧成
**「动作性措辞」**（`试一次|试一条|小范围跑|我建议先试…`）。

收紧之后误报确实归零（0/70 实测）。**但我只量了误报这一侧。**

产品自己的词汇不是「试一次」，是「**核心命题是……；观察窗口……**」。
用动作动词去认一个用命题-观察窗表达的探索提案，认不出来。

**我在冻结前跑了 70 例的误报普查，没有跑漏检普查。** 这是方法上的漏，不是运气不好。

## 3. 漏检有多大（事后补量，用粗代理）

代理判据：正文含 `核心命题|主要假设|要验证的是|观察窗口` 而 `explore` 未触发。

```text
正式重跑 58 例（保真 9 + 行为 49）        7/58
A/B 候选臂 3 次                            2/3   （HOLD-02、HOLD-03）
```

代理很粗，7 例里未必每例都是真的探索提案；但 `HOLD-03` 那一例是**由三名独立判定者
各自确认**的真漏检，不是代理推出来的。

## 4. 为什么不在本轮改

改触发判据 = 又一次锁定变量变化 ⇒ 按 A3 又一轮全量失效与重跑。
按 Founder `CONTINUE_TASK` 第 5 条，本轮之后**只有绑定冻结 AC 的发现可以阻断**——
这一条绑定 `M3-AC-08`（稳定兑现／受控探索／有限实验）与 `M3-AC-18` 的实验设计维，
**因此它阻断，登记为需要 Founder 决定是否再开一轮的事项，执行侧不自行开轮。**

## 5. 如果要修，正确的修法（备查，未执行）

不要继续往关键词表里加词——那是第 4 轮那条路，加到最后必然回到 fail-open。
方向应当是**从结构而非措辞判**：

- 正文里出现「命题/假设」+「观察项」+「观察窗」三者共现 ⇒ 按探索处理；
- 或者反过来：把探索六项从"触发才要求"改成"**只要正文提出了任何要在未来读数的东西，就要求**"，
  让触发条件本身变成一个从**输出结构**算出来的量，而不是从词表算出来的量。

无论走哪条，**这一次必须同时量误报和漏检两侧**，只量一侧就是这次的错误重演。
