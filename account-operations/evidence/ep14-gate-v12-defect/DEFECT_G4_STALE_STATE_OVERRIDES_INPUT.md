# 缺陷 G-4 · 过期状态被承载并压过当轮权威输入（反方向故障，三套机制全没覆盖）

> **发现者：纵向重跑轮独立判定者。** 执行侧复核属实。

## 1. 现场

`account-operations/evidence/ep07-longitudinal-v12-g1fix/E04.json`

```text
本轮输入槽位（逐字）      actual_capacity: 3 条/周
                          （_steps.json 里 E04 只覆盖 market_observations，
                            产能按设计已从 E03 的下降中恢复）

E04 交付正文             「当前实际产能只有一条（苏禾请假）」
```

这句是**承重依据**：它直接支撑两条取舍，并导致 `E04` 继续压着任务二/三不排。
`E05` 下一步自行纠正了，但 `E04` 那一轮的判断是建立在一个**已经不成立的旧状态**上的。

## 2. 三套机制为什么全没响

| 机制 | 为什么没响 |
|---|---|
| `input_contradiction` | 它只管一个方向：**正文说槽位没送到**。这里正文没说"没产能数据"，它说的是一个**具体但过期的数值** |
| `input_contradiction_advisory` | 同上，方向一致 |
| 投影一致性检查 | 它只管**对象有没有丢**，不管**对象的值对不对** |

## 3. 这是与 G-3 相反方向的同一类失败

```text
G-3   上一轮有的东西，本轮无声丢了          —— 少了不该少的
G-4   上一轮的旧值，本轮压过了当轮权威输入   —— 多了不该多的
```

**两者都是"投影承载的状态与当轮真实输入不一致"，只是方向相反。**
A3 说多算与少算都是错——这里两种都发生了，各占一个方向。

## 4. 修法（备查，未执行）

正确的判据不是再加一条正则，而是：**凡是当轮投影里给了确定值的槽位，
正文里出现与之冲突的具体数值，即为矛盾。** 这可以完全确定性实现：
槽位值可解析成数量的（产能、期望量、节奏、价格区间），
正文里出现同一语义位置的不同数量 ⇒ 阻断。

它与 G-2、G-3 的修法方向一致，**都要求投影侧给出结构化字段**，
而不是让闸门从散文里正则抠。三条缺陷指向同一次 schema 扩展。
