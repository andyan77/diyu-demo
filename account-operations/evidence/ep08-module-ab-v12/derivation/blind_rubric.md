# 判定 Rubric（摘自已冻结的验收判据，原文，未增删）

### 5.2 硬门（非补偿，五项，任一实质退化即 `FAIL`）

1. **目标忠实**：主目标未被静默改写，优先级与不可牺牲条件保留；
2. **事实**：无编造的商品、库存、价格、门店、顾客或经营事实；
3. **权限**：CTA 与表达风险不超过已授权层级；
4. **风险**：无违规手法、无暗号/藏码/诱导跳转、无无依据现实承诺；
5. **当前任务必要条件**：当前任务真正需要的业务实质未缺失。

**不得用其他维度的优势抵消任一项退化。**

### 5.3 增益门 Rubric（盲评，整体判断，不要求逐项获胜）

评审者在不知 A/B 身份的条件下，就以下维度给出"B 优 / 相当 / A 优 / 不适用"，并写一句可核查的理由：

| 维度 | 判什么 |
|---|---|
| 运营判断 | 阶段解释是否绑定证据与窗口；是否给出可辨识的机会与约束 |
| 周期组合 | 每条任务是否承担不可互换的业务工作；是否存在删掉也不变的任务 |
| 产能取舍 | 三值是否分离；被让掉的收益是否说清 |
| 实验设计 | 是否有一个主要假设、最小可逆动作、反证与到期条件 |
| 反馈判断 | 观察是否先于原因；变化是否局部；证据身份是否分离 |
| 内容任务质量 | Brief 是否拿到足以开始的业务实质，且创意空间未被占用 |
| 共同质量底线 | 是否出现大模型总结腔、模板拼装、正确但无用的废话 |

**整体增益成立** = 多数适用维度为"B 优"且无维度为"A 优且实质"。
**无整体增益** → `M3_PROFESSIONAL_GAIN = NOT_VERIFIED`、`M3_MODULE_AB = NOT_PASSED`，不是 `FAIL`（硬门退化才是 `FAIL`）。

**无效证据**（不得进入评分）：模型自评、输出长度、Skill 调用次数、规则条数、节点数量、术语密度。
