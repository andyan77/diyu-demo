## 一、生命周期必须区分的概念（冻结，不是互斥状态机）

```text
账号与周期
  → 内容任务
  → Brief／脚本／拍摄／包装产物
  → 内容版本
  → 发布实例
  → 效果观察
  → 下一周期判断
```

必须严格区分：**生成过｜被选中过｜制作过｜已发布｜已观察到效果**——这五项**不是五个互斥状态**，而是可以累积的五类生命周期里程碑／事实（一份产物可以同时"生成过、被选中过、制作过"）。

对应到 Execution Prompt §14 要求区分的完整概念集：任务／决策产物／内容修订／当前内容版本／候选／发布前人工评价／**真实发布实例**／**模拟或测试发布记录**／**真实市场效果**／模拟反馈／人工导入反馈／运营观察／因果提升结论——本文件逐一冻结这些概念之间的边界（§二～§五），具体是否落成枚举、如何转移由后续施工任务决定。

**只有实际发布的准确版本可以绑定效果反馈。草稿、候选和 PRE 包不能进入"已发布内容历史"。**

## 二、真实发布实例与模拟／测试发布记录必须严格区分（冻结）

> v0.2 §8.1 本轮纠偏补充的边界，本合同原样承接。

```text
真实发布实例 ≠ 模拟／测试发布记录
```

- 模拟／测试发布记录**不得**被记为、标注为或混入真实发布历史；
- 模拟反馈**不得**进入真实市场效果数据；
- 只有真实发布实例可以承载真实平台效果；
- **结构等价不代表业务身份等价**——一条记录即使字段结构与真实发布记录完全相同，只要来源是模拟或测试，就必须保留可区分的来源标注，不得因结构相同而被当作真实发布对待；
- 人工导入反馈必须保留**来源、时间、对象和可信状态**，不得匿名化为与系统自动采集反馈同等地位。

**没有真实账号、账号凭证、对外发布授权、平台实时可用性、已发生的真实发布、已取得的真实平台效果时，不得阻塞 M0—M5 工程构建与工程闭环验收**——工程验收允许使用明确标注的模拟发布记录、测试发布记录、人工导入反馈。

## 三、四类证据等级（冻结，互不蕴含，不得互相替代或夸大）

> 与 v0.2 §5.12.3、§8.1、§8.2 对齐，不新增独立验收框架。

| 证据等级 | 证明什么 | 需要什么证据 | 是否属于 M0—M5 阻断验收 |
|---|---|---|---|
| **工程闭环成立**（`ENGINEERING_VERTICAL_SLICE_VERIFIED`） | 工程数据流、版本归属、发布记录处理、反馈回流和跨周期机制已经验证 | 允许使用夹具、模拟或测试数据 | **是**——对应 v0.2 §8.2 第一、二层验收 |
| **专业价值增益** | 内容相对基线在专业维度有提升 | 盲式人工对照；不以模型自评代替 | **是**——不是独立评价轴之外的可选项，是[共享合同二](V1_M0_SHARED_CONTRACT_EIGHT_CAPABILITIES_v0.1.md#五m5增益性验收门phase-b附属验收语义)已冻结的阻断验收项之一。**正式标识符是共享合同二 §五定义的 `APPLICABLE_PROFESSIONAL_CAPABILITY_VALUE_ADDITION_PROVEN`，本表只做交叉引用，不另造第二个名称** |
| **真实运营闭环成立**（`REAL_OPERATION_LOOP_VERIFIED`） | 已存在准确的实际发布版本、真实发布实例和可归属的真实效果 | 准确真实发布实例 ＋ 可归属反馈 | **不是**——对应 v0.2 §8.2 第三层验收，缺失不阻塞 M0—M5 工程构建与收口 |
| **经营结果提升**（`OPERATIONAL_UPLIFT_PROVEN`） | 播放、涨粉、线索、到店或 GMV 实际提升 | 需要高于"真实运营闭环成立"的证据强度；单次发布、普通相关性观察或人工导入反馈不得被当作已经证明 | **不属于** M0—M5 工程验收范围，也不被"真实运营闭环成立"自动蕴含 |

> 与 v0.2 §8.1 对齐：以上名称是**产品验收语义**，不要求本合同把它们直接建设成 Runtime 枚举、数据库字段或状态机；具体如何落地由后续施工任务决定。

**尤其要防止的误读**：真实运营闭环成立不代表经营结果已经提升；专业价值增益成立不代表工程闭环或真实运营闭环已经验证；任何一类证据不得被拿来顶替另一类结论。

**模拟或测试数据只能证明**：系统能够正确接收发布记录；系统能够把反馈绑定到准确内容版本和发布实例；系统能够依据反馈形成下一周期调整或保持不变；幂等、版本归属和跨周期机制成立。**模拟或测试数据不能证明**：内容在真实平台有效；内容具有真实流量表现；内容真实吸粉；内容真实产生 GMV、线索或到店；真实运营闭环已经验证。**没有真实发布证据时，不得声明 `REAL_OPERATION_LOOP_VERIFIED`。**

**真实发布发生后，可以追加实际发布实例和效果证据，无需重开 M0—M5 建设任务。**

## 四、效果反馈必须分成三层（冻结）

```text
观测 → 解释假设 → 是否调整的决策
```

**观测**：播放；完播；互动；涨粉；线索；到店；GMV；用户人工评价。
**解释假设**：可能是钩子有效；可能是题材匹配；可能是分发条件影响；可能是发布时间或流量来源变化。
**决策**：下一周期是否调整；调整哪一层；是否继续验证；哪些判断保持不变。

**不得直接从数据跳到策略改写。**

人工反馈与市场效果必须分开绑定：**发布前**人工评审绑定候选或内容版本；**发布后**人工评价与市场效果绑定**准确发布实例 ＋ 观察窗口**。发布后反馈至少应能对应：准确内容版本；发布账号和平台；发布实例；观察时间窗；数据来源；分发条件；当前经营目标。

长期价值、起号、吸粉、流量和 GMV **不能压成一个总分**——长期价值不能只看短期播放；起号和吸粉不能只看 GMV；GMV 内容不能只看互动。初期允许用户人工录入或导入，不必立即连接所有平台 API。

## 五、反馈按责任组件定向回流（冻结）

| 反馈问题 | 回到哪里 |
|---|---|
| 内容比例、节奏、产能和周期组合 | 持续运营决策 |
| 单条任务定义不清或目标错误 | Content Brief |
| 题材、钩子、叙事、表达机制 | 创意锦标赛／Creative Script |
| 素材兑现、镜头和表演问题 | Production Director |
| 标题、封面、入口和发布表现 | Publishing & Packaging |

反馈优先路由至主要责任组件；存在多重原因时可以形成有限的跨组件诊断，**不得建立万能反馈池，也不得把相关性冒充因果关系**。四条限制：单条表现只是特定范围和时间窗内的观察，不自动成为因果事实；一次高表现不能证明某个钩子必然有效；一次低表现不能永久淘汰一个方向；反馈不能自动改写 Skill、Prompt、账号定位或长期目标。第一阶段的"学习"只表示下一周期决策获得了新的输入，不表示系统自动训练模型或修改规则。

## 六、局部修改与失效范围（冻结）

- 周期目标或账号定位发生**实质变化**，只影响仍在计划或制作中的相关任务；
- **已发布内容保留为历史，不转为 STALE**；
- Brief 或脚本**实际改变后**，才使依赖它的 PD／PP 产物失效；
- `realization_plan` 实质改变：影响尚未执行的拍摄安排，以及依赖旧计划的后续 manifest 和包装；
- `realization_manifest` 实质改变：影响依赖该 manifest 的 MIXED／FINAL 包装；
- **纯包装修改不反向**使脚本和导演计划失效；
- 用户提出修改但最终内容没变，下游不失效；
- 用户可以拒绝创意偏好回改；事实错误、权限和合规问题即使用户拒绝，也只能保留为历史草稿，不能重新成为可发布方案。

> 与[通用 EP-00](V1_REBASE_EP00_CURRENT_PREFLIGHT_v0.1.md) §九.2 冲突7 的对照：当前决策链五处 `fin_*` 节点是**无条件级联**（不比对内容哈希），与本节"未发生实际修改时下游不失效"的冻结语义相反，是已登记、待后续施工任务解决的真实差距，本合同不因此放宽上述冻结语义。
