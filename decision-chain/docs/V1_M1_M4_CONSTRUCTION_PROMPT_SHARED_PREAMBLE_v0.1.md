## 二、M1–M4 唯一责任与柔性并行

| 窗口 | 模块 | 唯一核心责任 | 不得越界 |
| --- | --- | --- | --- |
| W1 | M1 自然交互、任务上下文与能力路由 | 把用户自然语言编译为任务上下文，并按能力合同选择必要组件 | 不形成 M3 运营策略；不决定数据库物理结构；不重写专业 Skill |
| W2 | M2 最小业务数据、版本与运营记忆 | 保存业务记录、当前有效状态、产物版本、发布实例与反馈，并提供受权限约束的任务投影 | 不判断内容策略、账号定位、创意质量或 Skill 选择 |
| W3 | M3 运营状态诊断与持续运营决策 | 决定周期内为什么做、做什么、先验证什么、投入多少资源，以及依据反馈调整或保持不变 | 不建立第二套 Matrix；不决定单条内容具体如何创意、写、拍或包装 |
| W4 | M4 现有能力组件化接入与兼容改造 | 让八项能力具备合法直接入口、等价输入、组合调用、局部回退与局部失效，同时保持专业能力 | 不重建 M1 路由、M2 数据层、M3 运营逻辑、第二套锦标赛或生产链 |

“四窗口并行”表示当前四个施工 Prompt 规划窗口可逻辑独立、柔性错峰启动，不要求物理时间同时打开。Founder 可以任意先启动一个规划窗口，数小时或数日后再启动其他规划窗口。各窗口必须引用同一版本的本前言；先启动不取得修改共同语义、替其他窗口作决定或直接开始工程施工的权力。只有对应窗口的完整施工 Prompt 获得独立授权后，该窗口的工程施工才可错峰启动。

任一窗口发现共同语义需要变化时，只提交影响面和证据，不得静默修改本前言或四份共享合同。仅在对应窗口工程施工已经获得授权后，技术实现差异才由执行侧在既定边界内处理；改变用户流程、默认策略、目标优先级、模块责任或 MVP 范围时才返回 Founder 裁决。

## 三、八项能力共同继承规则

1. “必需业务输入”是当前能力完成本次判断所需的最小业务语义，不是固定表单、完整夹具或一整份上游产物。
2. 用户自然语言、合法资料、持久化投影、有效历史产物或其他组件产物，只要业务核心语义充分，都可以成为合法等价输入；但来源、确认状态、权限、作用域、时效和证据等级必须保留，语义等价不等于证据或权限等价。
3. 不设一份横跨八项能力的全能资料准入表。缺少非阻断信息时，应条件化、暂定化或降级运行；只有事实、权限、合规、用户明确不可牺牲条件、当前能力真正必要的输入缺失，或 `V1_SINGLE_ACCOUNT_SLICE_CONTRACT_v0.2.md` §8.7 已点名的门禁项，才阻断对应分支。不得把该清单扩大到建议性专业资料。
4. 合法等价输入满足时可以跳过物理上游组件；不得暗中补跑 Matrix、Campaign 或其他不需要的能力，也不得把旧的线性链恢复为唯一入口。
5. 用户已明确提出任务时，该意图覆盖任务范围内必要的可逆生成和内部组件调用；不得在能力之间逐层索要固定口令或重复确认。对外发布、正式版本写回、权限变化、不可逆动作和长期规则变化仍按共享合同四处理。
6. “实质修改”指被下游实际消费的业务含义发生变化。排版、措辞、说明文字、重跑但结果未变，或用户提出建议但最终没有采纳，不触发下游失效。
7. 失效必须依据真实依赖局部、定向、向后传播；不反向传播，不无条件级联整条链。已发布内容及其准确发布实例保留为历史，不因上游后来变化而失效或被改写。
8. 草稿、系统建议、候选或暂定判断只有按共享合同四成为当前有效版本后，才能替代既有有效版本；模型自评不能单独完成替换。
9. 专业能力是按任务适用的能力义务，不是每次必须依次调用全部六份 Skill 的全能硬门。用户已有合法等价输入时可以跳过组件，但当前下游真正必要的输入和适用质量条件不得无声消失。
10. 目标可以改变选题优先级、钩子强度、节奏、密度、实验比例和 CTA 方向；不得把流量、起号、吸粉、GMV 等目标重新改写成长线价值任务，也不得以目标不同为由旁路、削弱或中性化适用专业方法。
11. 模拟／测试反馈只能证明工程机制会正确处理该类输入，不证明真实平台效果或经营提升；真实运营观察也不得被夸大为因果经营提升。

## 四、八项能力的四类业务合同值

### CAP-01 账号架构与诊断（Matrix）

**必需业务输入**

- 当前请求确实涉及长期账号定位、人设、账号职责、表达主体关系或多账号结构的建立、诊断或实质修改；
- 已识别的主体、工作空间和账号范围；
- 足以支持本次长期主张的个人、品牌、业务、顾客、商品／服务、表达主体及其可持续表达条件等事实，以及来源、确认状态、权限和约束；
- 已有定位、人设或账号责任版本及其有效状态；不存在时明确记录为空白，不得伪造。

仅做探索、运营现状观察或不涉及长期结构的任务，不要求先补齐完整品牌档案或先运行 Matrix。

**合法等价输入**

- 用户自然语言中的个人／品牌介绍、业务说明、账号现状和表达意图；
- 已确认的账号档案、Matrix 产物、账号责任卡或长期定位版本；
- 合法历史内容、账号表现和外部参考可作为观察材料，但不能自动升级为用户确认的长期定位；
- 信息不足时可形成明确标注的暂定画像或探索假设，但不能冒充当前有效长期真源。

**输出**

- 长期账号架构或单账号诊断结论，包括账号使命、受众问题、定位、人设、账号职责、表达主体关系及多账号关系；
- 事实、专业判断、已确认部分、暂定部分、缺口、适用范围与成立条件的清晰分离；
- 若当前不足以建立正式定位，输出可继续探索的边界和最小追问，而不是虚构结论或拒绝整个任务。

不输出周期目标、内容组合、日常排期、脚本、拍摄或包装方案。

**实质修改后的下游失效**

- 只有当前有效的定位、人设、账号职责、表达主体关系、事实权限或长期表达边界发生实质变化时，才使实际依赖该变化且仍处于计划或制作中的周期、Campaign、内容任务、Brief、创意、脚本、制作和包装产物局部失效；
- 不影响无真实依赖的任务；候选或 `INPUT_INSUFFICIENT` 本身不触发失效；已发布内容保留为历史；
- M3 发现长期定位可能失配时只提出 Matrix 复核请求，不自行改写定位真源。

### CAP-02 单次经营任务策划（Campaign）

**必需业务输入**

- 有明确时间或阶段边界的经营任务；主目标、有限次目标、优先级和不可牺牲条件；
- 目标受众及需要回应的问题、场景或机会；可用事实、素材、人员、产能、表达裁量和风险边界；
- 涉及咨询、线索、到店、购买或其他承接时，对应目标和有效承接路径；
- 作为周期覆盖层运行时，需有当前周期基线、覆盖范围和恢复边界。

**合法等价输入**

- 用户直接提出的新品、节日、阶段传播或转化任务；
- M3 周期内的临时覆盖任务；已确认的账号／品牌／人员／产能投影；合法历史 Campaign 或经营决定；
- 已有完整决定集时可以进入现有“编译已确认决定”兼容模式；没有时仍可使用正式策划能力，不强制用户手工制作决策包；
- Matrix 或账号责任卡只在本次 Campaign 确实涉及长期账号分工时才是必要输入。

**输出**

- 有期限的 Campaign 决策包：目标与取舍、参与主体、内容组合与顺序、产能、CTA／承接条件、取消或缩减条件、观察信号；
- 周期覆盖模式下明确覆盖范围、与周期基线的冲突以及结束后的恢复条件；
- 进入 Brief 的内容任务使用统一内容任务语义，不另建 Campaign 专用格式。

不得把起号、吸粉、流量、GMV、线索或到店静默改写成“认知变化”，也不输出完整脚本、镜头或发布包装。

**实质修改后的下游失效**

- 期限、目标、优先级、参与主体、内容取舍、事实链、产能、CTA 或覆盖范围实质变化时，只使受影响且未发布的 Campaign 内容任务及其下游失效；
- 覆盖层只影响其点名占用的位置；结束后恢复仍有效的周期基线；不反向改写 Matrix 或无关的 M3 判断；已发布内容保留为历史。

### CAP-03 单账号持续运营能力（M3）

**必需业务输入**

- 账号范围、经营目标与优先级、不可牺牲条件、表达裁量、平台条件和信息来源状态；
- 诊断时：账号阶段、已有定位或暂定锚点、当前表现和可用市场观察；
- 周期规划时：周期、期望发布量、基线与当期实际产能、事实素材、内容历史、既有栏目和实验；
- 日常决策时：当前周期计划、当日任务、实际素材、可用产能和近期重复情况；
- 复盘时：准确内容版本、真实或测试发布记录、反馈、观察时间窗、证据身份和外部变化。

若声称跨会话、跨周期持续运营，必须能取得可恢复的 M2 业务投影；没有持久化时只能完成当次诊断或计划，不得声称闭环成立。

**合法等价输入**

- 用户自然语言提供的账号状态、目标、产能、历史和反馈；
- 已确认或明确暂定的 Matrix 结果；M2 的账号／周期／任务／版本／发布／反馈投影；Campaign 覆盖层；合法历史内容、人工录入反馈和市场观察；
- 模拟／测试反馈可用于工程验证，但不得当作真实运营效果；没有正式定位但有足够起始锚点时可先诊断，不强制先跑 Matrix。

**输出**

- 按需要输出运营状态诊断、周期规划、日常决策或复盘更新；
- 明确稳定兑现、受控探索、长期价值积累与转化任务之间的取舍，并允许少发、延期、调整结构、增加资源或不发；
- 反馈充分时局部调整，反馈不足或矛盾时有依据地保持不变；相关性不冒充因果；
- 统一内容任务至少包含：来源、周期角色（不适用时明确标注）、一个主目标和有限次目标、优先级与不可牺牲条件、受众问题／场景／机会、希望观众发生的变化、内容承诺／核心命题／待验证假设、账号阶段与表达边界、事实素材与缺口、平台／内容类型、可用产能和观察项。

M3 到此停止，不决定具体钩子、完整叙事、台词、拍摄机制或包装方案。

**实质修改后的下游失效**

- 阶段、目标、优先级、内容组合、节奏、产能、实验或复盘结论实质变化时，只使受影响且未发布的内容任务及其下游失效；未受影响任务保持有效；
- 不因反馈不足而制造变化，不因一次高表现把整个账号收敛成模板号；下一周期变化不反向使历史周期或已发布内容失效。

### CAP-04 Content Brief

**必需业务输入**

- 一个选中的单条内容任务或明确选题；一个主目标、有限次目标、优先级和不可牺牲条件；
- 受众问题／场景／机会、希望观众发生的变化、内容承诺／核心命题／待验证判断；
- 表达主体及责任边界、事实／素材／来源／缺口、表达裁量、权限与合规边界；
- 内容形态、目标平台或明确未知状态、可用产能和生产条件；涉及 CTA 时的目标、授权和有效承接路径。

不属于周期的用户直接任务可以把周期角色标为“不适用”，不得虚构周期。

**合法等价输入**

- M3 内容任务、Campaign 内容任务、用户直接明确选题、合法历史产物或满足必要语义的已有脚本构想；
- 用户自然语言、资料与历史内容的组合，只要足以形成单条内容的业务核心；
- 不要求 Matrix 或 Campaign 产物，不得暗中补跑。

**输出**

- 单条内容生产合同：任务来源、唯一主要工作、受众问题与期望变化、核心命题与内容承诺、事实证据链、必须使用／不得使用内容、生产条件、CTA 与发布／降级／取消条件；
- 每条 Brief 保持一个主目标；必要时可拆成多条独立 Brief；
- 不输出完整逐字稿、逐镜分镜、最终标题、封面或发布文案。

**实质修改后的下游失效**

- 主目标、受众问题、核心命题、内容承诺、事实证据、表达边界、素材条件、CTA 或生产条件实质变化时，只使依赖该变化的创意、脚本、PD 与 PP 产物失效；
- 说明性补充或业务含义未变不触发失效；未变化的其他 Brief 保持有效；已发布内容保留为历史。

### CAP-05 创意决策／创意锦标赛

**必需业务输入**

- 单条内容任务、Brief 或等价输入中的主目标、受众问题、期望变化与内容承诺；
- 事实、素材、来源、缺口、明确不承诺事项、表达主体、表达裁量、风险边界、内容形态、平台和生产约束；
- 可靠市场观察可用于判断，但不是普遍准入门。

**合法等价输入**

- 完整或最小合法 Brief；用户直接给出的选题、创意需求或已有方向；合法历史方向或参考；满足单条创意判断条件的 M3／Campaign 内容任务；
- 用户已选定实质方向时可直接交给 Creative Script，不强制再举办锦标赛。

**输出**

- 确有选择时提供实质不同且可比较的方向，说明核心机制、事实与素材前提、适用条件、代价和失败条件，并推荐或记录选择；数量由任务决定，不固定；
- 没有实质选择时直接给推荐；候选在用户选择前不得被确定性抹掉；
- 只输出创意方向，不再次编写完整脚本。

**实质修改后的下游失效**

- 当前有效的选中方向、内容机制、核心矛盾、信息释放方式、表达主体或事实前提实质变化时，使依赖它的 Script、PD、PP 局部失效；
- 未选候选变化、仅比较尚未改选或说明文字变化不触发失效；已发布内容保留为历史。

### CAP-06 Creative Script

**必需业务输入**

- 已选创意方向，或足以合法触发单条创意判断的明确任务；
- 主目标、受众变化、内容承诺、表达主体和表达条件；
- 事实、原话、观察、设定、素材、来源方式、明确不承诺事项、权限与表达边界；
- 内容形态、时长、平台和生产资源；非阻断缺失可采用显式的平台中立或低资源条件。

**合法等价输入**

- Brief、用户直接选题与必要事实、已选方向、合法历史任务／概念／脚本骨架、明确虚构设定；
- 用户已有满足 PD 输入条件的脚本时可以跳过 CS；资料不足时输出可安全形成的脚本部分、结构骨架、最小问题和缺口，不以一句“信息不足”结束整个任务。

**输出**

- 完整脚本或安全的部分产物，包括内容承诺、明确不承诺、节拍、台词／旁白／屏幕文字、事实与素材状态、证据要求、资源约束、假设、缺口和失败方案；
- 面向 PD 的可执行结构，并真实处理下游回改：实际修改，或有依据地保持不变；
- 不输出完整机位、分镜、制作调度、标题、封面或发布文案。

**实质修改后的下游失效**

- 内容承诺、节拍、台词、事实引用、素材需求、表达主体、明确不承诺或生产约束实质变化时，只使依赖相应单元的 PD 计划／manifest 与 PP 包装失效；
- 不影响制作／包装的文字修正不机械重跑整链；改变核心承诺时应定向回到 Brief／创意层；已发布内容保留为历史。

### CAP-07 Production Director

**必需业务输入**

- 已有脚本或在业务含义和可制作结构上等价的内容方案；
- 内容节拍、事实与素材状态、内容来源方式、受众变化、内容承诺、事实边界与明确不承诺事项；
- 生产资源、时间窗口、可用／待检索素材、表达主体、内容形态、时长、平台和制作约束。

内容来源方式无法确定时不得静默默认现拍。

**合法等价输入**

- Creative Script、用户已有完整脚本、具备节拍／事实／素材／承诺／约束的历史脚本或方案；
- 已有素材剪辑、图文、纯音频、访谈或生成视觉任务均合法，不要求必须实拍；
- 局部事实或素材不足时可设计待成立单元、检索路径或降级路径，不把整个任务退回。

**输出**

- 拍前 `realization_plan`：场景、动作、制作单元与脚本节拍覆盖关系，拍摄／检索／生成／动画／音频／文字计划，表演指导、素材清单、顺序、声音、剪辑、关键帧、补拍／补录和低资源版本；
- 素材回来后的 beat 级 `realization_manifest`，准确记录实际兑现；
- 必要时 `return_to_script`，不自行改写脚本；事实、素材、授权和不承诺事项原样透传。

**实质修改后的下游失效**

- plan 实质变化只影响尚未执行的制作安排、依赖旧计划的 manifest 与 PRE；manifest 实质变化只影响依赖它的 MIXED／FINAL；
- 局部制作单元变化只影响对应包装和兑现判断；已完成且仍被保留的单元不重复执行；已发布内容和旧 manifest 保留为历史。

### CAP-08 Publishing & Packaging

**必需业务输入**

- 准确内容正文、脚本节拍或等价的成片内容说明；内容承诺和明确不承诺事项；事实及来源；
- PRE 需要制作计划；MIXED／FINAL 需要能按节拍确认实际素材覆盖的 manifest 或合法等价成片证据；
- 目标平台；未知时只能形成平台中立母版；表达主体／账号包装定位、CTA 目标／授权／承接边界和素材发布权限。

**合法等价输入**

- Script＋PD 产物；用户已有脚本、计划或真实成片信息；已有合法成片及足以确定兑现内容、事实、授权和平台条件的说明；
- 图文、音频、已有素材剪辑等非视频信息；只有计划时可进入 PRE，不得冒充 FINAL；
- 有合法成片时不得强制补跑 CS 或 PD，应通过适配取得必要语义。

**输出**

- 基于证据推导的 PRE／MIXED／FINAL 状态和依据；实际兑现、缺口及处置；
- 通用母版和平台适配：标题、封面、首帧、发布文案、字幕、音乐／音效、评论区、CTA、作者转发语；
- 有实质选择时给包装候选和推荐，数量不固定；发布前检查、事实回指、发布承诺上限、可发布条件及定向 Returns；
- 面向用户的精简可行动交付，不把内部状态码和冗长底稿当成最终交付。

**实质修改后的下游失效**

- 包装自身变化不反向使 Script、Brief 或 PD 失效；上游正文、承诺、plan 或 manifest 变化，只使依赖部分的包装和可发布判断失效；
- 平台或 CTA 权限变化只影响相关平台变体、CTA 与发布条件；
- 发布后发生修改时必须形成新的内容版本；只有该新版本实际对外发布时才形成新的发布实例。未再次发布的修订不得产生或冒充发布实例，不得改写旧发布历史；只有实际发布的准确版本才能绑定真实效果。

## 五、Matrix 资料不足的统一降级与局部阻断

1. 仅在建立或实质修改长期定位、人设、账号职责、表达主体关系或多账号结构时调用 Matrix；不适用时直接绕过，不得暗中补跑。
2. 缺少非阻断信息时，可输出带成立条件、假设和缺口的暂定判断，但不得写成当前有效长期真源。
3. 缺少完成本次 Matrix 判断真正必要的信息时，只追问当前最具区分力的一项；不得要求用户重填整套夹具。
4. 只暂停真实依赖 Matrix 结论的分支。已有合法输入的 Brief、PD、PP、Campaign 及其他无关诉求继续。
5. 事实、权限或合规缺口只阻止相应正式写回、发布或现实承诺，不扩大为整任务拒绝。
6. `INPUT_INSUFFICIENT` 是当前分支结果，不是整任务终态，本身不触发下游失效。
7. 只有已经成为当前有效版本的长期对象发生实质变化，才按真实依赖检查未发布下游；历史发布不回写、不失效。

模块承接：M1 负责判断 Matrix 是否适用、编译等价输入与缺口、提出最小追问并继续无关意图；M4 负责把现有 Skill／DSL／路由的全局终止改造成组件级或分支级返回并验证无衰减；M2 保存暂定／当前有效状态、来源和依赖，不作 Matrix 专业判断；M3 消费有效定位或建议 Matrix 复核，不建立第二套定位真源。

## 六、跨模块接缝

### 6.1 M1 → 其他模块

M1 输出业务核心等价的任务上下文投影，保留用户原话和相关叙事资料的引用；不要求用户把自然语言重填为结构化表单。M1 只决定“当前需要哪项能力”，不替专业组件作深度判断。

### 6.2 M2 → M1／M3／M4

M2 提供受权限、作用域和时效约束的任务投影，区分事实、偏好、参考、假设、缺口、当前有效版本、发布实例和反馈身份。Dify Memory 不是业务真源。运行接口可保留与判断相关的用户原话、故事片段和资料引用。

M2 还需能够记录可跨多个内容任务重复验证的“打法”及其观察状态；“打法”不是单个选题、单条内容或抽象目标。状态语义与正式写回权限由 M0.3 合同约束，物理枚举和数据库结构不在本前言冻结。M3 提议变化，M2 负责记录。

### 6.3 M3／Campaign → Content Brief

M3 与 Campaign 使用同一种内容任务业务语义，不建立两套任务单。任务来源不是封闭枚举：持续运营、Campaign、用户直接任务和合法历史产物均可成为合法上游。来源不同只增加来源标识，不改变 Brief 所需的业务核心。

Campaign 作为周期覆盖层时，只占用其点名的内容位置；未覆盖位置及 Campaign 结束后的周期基线仍由 M3 管理。两者不得静默修改对方的当前有效内容。

### 6.4 M3 与创意／生产能力

M3 负责赛道机会、题材饱和、内容支柱、栏目疲劳和周期组合层的同质化判断；创意锦标赛／CS-1 负责单条内容的题材切入、钩子、叙事和表达机制差异；PP 负责标题、封面与入口包装的竞争性和平台适配。

没有可靠市场资料时不阻塞生产，但不得声称已经完成外部比较；有来源、时间和覆盖范围足够的可靠证据证明高度同质时，受影响层必须改版或不发。外部同质化检查先于账号自身重复检查。

M3 模块验收只证明目标忠实、阶段判断、内容组合、产能取舍、实验设计、反馈纪律和内容任务可用性，以及其输出没有压制或丢失后续适用专业能力。钩子、创意、活人感、叙事、共情、人设、可拍性、转化自然度和成品完成度由 M5 集成验收；适用性维度允许标记“不适用”，不得变成每条内容统一硬门。

## 七、仍须在模块施工 Prompt 中定责的物理问题

以下事项已有业务合同，但当前真源不能唯一确定物理实现。各模块施工 Prompt 必须先明确哪些由规划侧冻结、哪些在工程授权后保留给执行侧；不得仅凭本前言自动开工或自行取得产品架构裁决权：

1. M3 是扩展既有能力、增加适配层还是新增独立 Skill，由 W3 规划侧结合专项 EP-00、项目外 M3 构建方案和规划侧唯一成稿，在 M3 施工 Prompt 中冻结；执行侧不得自行三选一。若后续授权新建 Skill，其外部研究资料包与唯一成稿由规划侧另行提供，不在本前言或桌面快照中复制。
2. 创意锦标赛继续寄居 CS-1、拆节点或由适配层调用；产品语义要求其能力存在，不要求新建独立 Skill。
3. Matrix 正式定位所需事实的具体组合与阈值；不得重新冻结通用必填表。
4. PP 如何从合法成片信息提取等价业务语义；不得因当前 Skill 形态恢复完整上游硬门。
5. 下游依赖用内容哈希、版本引用、显式依赖或其他最小机制记录；不得建设重型依赖图或事件溯源。
6. 容量核算、日期窗口、去重等简单确定性计算是否需要最小工具；如确有运行证据需要，优先归 M2 或应用后端，不塞进 M3 专业判断。

业务持久化是否复用现有 PostgreSQL，以及采用独立数据库或独立 Schema，仍按共享合同四 §一处理；在取得对应裁决前，M2 可以完成需求、边界和候选技术方案编译，但不得自行把某一拓扑写成已冻结实施方案。

以下是已知施工差距，不是待重新裁决的产品语义：决策链全有全无式硬停、Content Brief 对 Campaign 的唯一上游锁、Campaign 目标窄化／兼容模式降权、固定候选数量、PP 无法凭合法成片直达、决策链无条件级联失效和生产链缺少局部失效机制。它们应进入受影响模块的施工 Delta，不能反向污染本前言。

## 八、四窗口施工 Prompt 的共同编译要求

每个窗口的施工 Prompt 必须：

1. 继承本前言和四份共享合同，不复制改写共同产品目标；
2. 明确本窗口负责的 Delta、受保护能力基线、接口依赖、非目标和模块验收；
3. 只把本窗口真实影响的旧能力列入回归，禁止开放式全仓复验；
4. 把当前仓库事实、目标合同和施工 Delta 分开；不得把 EP-00 的 `MISSING`／`CONFLICT` 写成已修复；
5. 明确工程实现尚须 Founder 对该窗口的独立 Execution Prompt 授权；本前言被采用不自动开工；
6. 使用稳定 ID、路径和内容指纹引用，不在正文写会自然过期的轮次、数量和“第 N 条”定位；
7. 不把普通可逆生成、内部组件调用或用户提出的具体调整方向升级成 Founder 审批门；系统必须实际响应合法调整，或给出可核验的事实／权限／合规理由；
8. 区分工程纵向切片通过与真实运营闭环通过，不把模拟数据或有限真实观察夸大成经营提升；
9. 不新增第二套路由、工作流引擎、数据库治理、知识库、RAG-first、Judge 网络、评分平台、自动实验优化器或全面 Skill 重写。

本前言采用后，四窗口可按 Founder 选择的顺序分别进入施工 Prompt 编译；只有 Founder 接受某一窗口的完整施工 Prompt 并授权执行，该窗口才可开始工程施工。
