## T-01 · M4-FND-011：接缝无产出完整性守卫 —— 解冻修复，还是带缺陷收口？

**严重度**：HIGH ｜ **影响**：AC-17 盲评合取项（唯一真被阻断项）

### 事实

接缝把 `artifact`（内部专业产出）与 `user_delivery`（用户交付块）**在一次 LLM 生成内靠文本标记切分**，
下游 code 节点按标记解析。**内容往哪块倒逐次重掷**，可塌成回指或空块。

四环根因，均为直接观察：

1. 两块靠 `---M4_ARTIFACT---` / `---M4_USER_DELIVERY---` 文本标记切分，非结构化输出
   （`DIYU_M4_TOOL_*_v1_3_TEST.yml` prompt「产出结构（三块，标记行原样照抄）」）
2. prompt 要求两块都「完整」，但**无一句禁止两块互相回指**，也未设非空下限
3. `§7 输出前内部检查` 12 条全为内容纪律，**无一条检查两块是否都写了**
4. 六个「接缝收口｜*」code 节点均为 `"artifact": tool_artifact or ""` /
   `"user_delivery": tool_user_delivery or ""` —— **缺失被静默转成空串并按成功放行**，
   无非空守卫、无长度下限、无失败分支

放大器（非根因）：`completion_params: top_p 0.8 / thinking true / reasoning_effort low / temperature 未固定`

**实测**：57 次成功运行中 10 次塌陷 ≈ **18%**。AC-17 A 侧同一份逐字节相同输入跑 3 次：
859 / 5514 / 6073 字（7 倍差）。全部 `status=succeeded`、`total_steps=6`，无节点失败。
塌陷运行 `total_tokens` **更少**（14959 / 16140）而非撞顶，**排除 max_tokens 截断**。

**归属**：M4 自有资产（接缝 DSL + Tool prompt），**非 M1 外部依赖**，与 FND-002 不同类。

**失效传播（A3，逐条机器核对）**：**零条已记录判定被推翻**。所有引用了塌陷运行的
`PASS`/`FAIL` 合取项，其证据引文均逐字出自该运行**存活的那一块**。
唯一真被阻断：**AC-17 盲评合取项**（需 A/B 两侧完整产出做形态可比对照）。

### 待裁问题

在 Founder 已下达代码冻结令的前提下，本缺陷**是否解冻修复**？

### 选项

| | 方案 | 代价 |
|---|---|---|
| (a) | **带缺陷收口**：登记为已知缺陷，最小改法留给后继版本 | 每次运行 ~18% 重跑浪费；缺陷带入后继版本 |
| (b) | **最小解冻**：只给六个收口节点加非空 + 长度下限守卫，走 `PARSE_FAIL` 分支 | 须重新发布接缝 → 接缝版本变化 → 直接撞 `AC-16` 合取项④「九个保护应用绑定零变化」，并命中 N-20（tool 版本注册时钉死、重发布不同步，本任务已踩过一次）→ **57 次运行的绑定全部 STALE，验收从头再来** |
| (c) | 只改采样参数（固定 temperature / 关 thinking） | **执行侧明确不建议**：参数是放大器不是根因，改它会掩盖守卫缺失，让缺陷更难被发现 |

### 执行侧倾向

**(a) 带缺陷收口。** 理由：零条判定被推翻；82% 运行完整；(b) 的级联代价（全部绑定 STALE、
验收重来）远大于收益（消除 18% 重跑浪费）；(c) 掩盖根因。

最小改法已写入账本备后继版本：收口节点加非空 + 长度下限守卫，缺失走 `PARSE_FAIL` 分支
而非静默放行；prompt 显式禁止两块互相回指；**不动采样参数**。

### 不裁的后果

AC-17 可用 §1.3 采样绕过（见 T-02），但缺陷本身无处置结论，任务无法收敛终态。

## T-02 · 盲评取证方式：§1.3 预授权采样，还是单次为准？

**严重度**：HIGH ｜ **影响**：全部 11 项 `NOT_VERIFIED` 中依赖盲评的部分

### 事实

FND-011 使单次运行有 ~18% 概率形态塌陷。这与 **N-30**（「失败后盲目重抽、只留满意输出 ⇒ 禁止」）
形成夹击：

- 跑一次塌了就重跑、留满意的那次 → **正是 N-30 禁止的挑结果**
- 不重跑 → ~18% 概率白跑一张卡；成对对照要两边都干净，概率降至 ~67%
- **§1.3 预授权采样**（跑前冻结 N、全部保留、一并盲评，算**一次**）→ 唯一合规出路

**实证**：执行侧已按 §1.3 跑完 N=3（跑前冻结、12 份全部保留、塌陷样本不删不藏）：

| 判据 | 侧 | 完整/总数 | 可用性 |
|---|---|---|---|
| AC-17 | A | 2/3（S2 5514字、S3 6073字） | ✅ 形态可比集合成立 |
| AC-17 | B | 3/3（4961 / 5942 / 6712字） | ✅ |
| AC-05 | M3 | 1/3（S1） | ⚠ 可判，但厚度不对称 |
| AC-05 | CAMPAIGN | 3/3 | ✅ |

**AC-17 因此从「不可判」变为「可判」。**

### 待裁问题

1. §1.3 预授权采样是否适用于本任务全部盲评项？
2. 已跑完的 N=3 采样（`decision-chain/evidence/m4/samples/`）是否被接受为正式取证？
3. AC-05 的 M3 侧仅 1/3 完整（对 CAMPAIGN 侧 3/3），**是否需要加采到 3 份完整**？

### 执行侧倾向

1. **适用**。已实证有效。
2. **接受**。跑前冻结 N=3、全部保留、输入逐字节校验（`sha256` 断言）均已满足 §1.3 要件。
3. **不加采**。AC-05 判据问的是「12 项业务核心逐项同义」，**不依赖样本数**；
   加采只让表格对称，属 A5 该删的动作。若规划侧认为厚度对称本身是取证要求，则应加采。

### 不裁的后果

AC-05 / AC-17 等盲评项无合规取证路径，只能保持 `NOT_VERIFIED`。

## T-04 · M4-FND-007：AC-15 公平对照纪律不可满足

**严重度**：MEDIUM ｜ **影响**：AC-15（`NOT_VERIFIED`）

### 事实

AC-15 取证对象为「固定对照集（**同输入 / 同模型 / 同参数 / 同预算**）」。
实际两侧 `completion_params` 不相等：M4 后继版本带 `thinking: true`，源 v0.1 不带。
对齐需修改保护应用或修改冻结交付物，二者当前均被禁止。

**不对称性**：判「M4 明显劣于源版本」是有效 `FAIL`；判「不劣于」**不能记 `PASS`**，
因为公平对照前提不成立。

### 待裁问题

(a) 授权临时对齐参数再跑一次对照，还是 (b) 版本化修订 §3.1 公平对照口径？

### 执行侧倾向

**(a)**，且只对齐参数、不改其他，跑完即回滚。理由：(b) 是在看到「对不齐」之后放宽判据，
虽版本化仍有 A2 风险；(a) 是换取证条件不换判据，更干净。
但 (a) 需要解除冻结令的局部授权，**执行侧无权自决**。

### 不裁的后果

AC-15 永久 `NOT_VERIFIED`。

## T-07 · M4-FND-010：AC-28 高风险例未落 `cta_contract` 指名取值

**严重度**：LOW ｜ **当前状态**：`FAIL`

若规划侧认为判据本意是行为而非字面量，应版本化修订判据，而非由执行侧放行。

## T-08 · 本任务终态如何收敛

**严重度**：HIGH

### 事实

当前 `PASS 17` / `FAIL 2`（AC-21、AC-28）/ `NOT_VERIFIED 11`。
按内核 §4 终态判定顺序，`AC-01…30` 未全部 `PASS`，**不得宣告 `DONE`**。

其中 **AC-21 的 `FAIL` 已由 Founder 裁定**为 M1 外部依赖（`M4-FND-002`），
**不由 M4 越界修复**——即该 `FAIL` 在 M4 范围内不可消除。

### 待裁问题

M4 的终态取 `PARTIAL` 还是 `BLOCKED`？判定依据是什么？

### 执行侧倾向

**`PARTIAL`**。理由：`BLOCKED` 意味着无授权内路径可走，但 T-02 已证明盲评有合规路径、
11 项 `NOT_VERIFIED` 中多数只待 Founder 终结审查；AC-21 的 `FAIL` 归属 M1 而非 M4 能力缺失。
`PARTIAL` 如实反映「大部分成立、两项 FAIL 各有明确归属、余项待审」。

**执行侧不自行宣告终态**（CLAUDE.md §6：不得由执行侧把合同状态往上推一级）。
