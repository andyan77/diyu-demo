## 通用取样与判定纪律

- 每个正式输入**只跑一次**。纯传输失败且没有任何模型输出时最多重试一次，两个 Attempt 都保留。
- 禁止同输入重复采样求 PASS。
- 平台 `succeeded` **不等于**业务交付。业务真相只认接缝的 `business_delivery_outcome`
  与 M2 的真实数据行。
- `modules_actually_run` 以 Dify `workflow_node_executions` 的实际节点记录为准，不认模型自述。
- 用户可见输出的判据是 `uapp_delivery.leak_hit_count == 0` **且** 人工复核回复正文中
  不出现内部状态词、字段名、节点名、app_id、ENTRY-xx、能力枚举。

## 正式用例

### UAPP-FULL-01｜同一会话完整主故事（AC-03 / AC-09）

多轮，同一 `conversation_id` 与同一 end-user。

1. 自然语言经营诉求（含受众、问题、期望改变、表达边界、商品事实）→ 期望：形成 M1 上下文、
   M2 当前投影真实返回、M3 给出周期判断、至少一个适用 M4 专业能力真实运行并产出产物；
   产物与版本被登记进 M2（`should_persist_artifact=true` 且 artifact/version 均 2xx）。
2. 「这条我已经发出去了」→ 期望：登记一条 `is_test=true / is_simulated=true` 的测试发布记录；
   系统明确说明这是测试记录、没有对任何真实平台操作。
3. 「收到的反馈是……」→ 期望：反馈按版本幂等写回 M2；重复提交同一条不产生第二行。
4. 「这个周期结束了，开下一个」→ 期望：M2 出现新周期。

**PASS 条件**：四步的 M2 写入全部可在数据库里查到对应行；`modules_actually_run` 与实际
节点执行记录一致；全程零泄漏；第 2 步之后系统不得声称任何真实平台发布。

**FAIL 条件**：任一步声称写入成功但库里查不到；或出现真实平台发布语义；
或 `is_test/is_simulated` 不为真。

### UAPP-CAP-01..06｜六项能力各自可达（AC-04）

六条独立会话，各一句自然语言，**不点名内部枚举**，只说人话。每例判据相同：

- `uapp_route.target_capability` 等于该例预期能力；
- `uapp_seam` 节点实际执行且 `capability` 参数为该能力；
- 未被点名的其余五个能力**没有**被调用（`modules_actually_run` 里只有这一个）。

不要求同一例跑完六个能力；不要求每例都产出成品——能力真实进入并给出结论或精确缺口即算可达。

### UAPP-GAP-01｜缺关键商品/方向时精确停（AC-06）

输入：只说「这周想发点东西，你看着办」——不给商品、不给方向、不给受众。

**PASS**：系统停在**精确缺口**并只问真正阻塞的那一项；不替用户挑商品、不替用户定方向；
不整任务拒绝（不依赖该缺口的部分照常给出）。补齐后在同一会话继续，不要求重述已给内容。

**FAIL**：自选商品或方向；或整任务拒绝；或用内部字段名向用户提问。

### UAPP-WITHDRAW-01｜撤回影响面与副作用真实性（AC-07）

前置：同一会话已上传一份素材并已登记测试发布。
输入：「把刚才那份素材撤回，别再用了」。

**PASS**：回复必须把四件事**分开**说——(a) 这份素材未来不再用于新内容；
(b) 已经发出去的内容不受影响、没有被删除；(c) 没有对任何真实平台做操作；
(d) 本轮实际写入了什么。且 M2 里该素材确实进入撤回态。

**FAIL**：把撤回影响面扩张到已发布内容；或声称做了平台操作；
或在 M2 没有 2xx 的情况下声称撤回已完成。

### UAPP-EQUIV-01｜等价表达一致 + 缺项负例精确 Return（AC-08）

三条**语义充分且等价**的表达（普通中文 / 带引号的 YAML 式书写 / JSON 式书写），
各自独立会话。**PASS**：三者的 `target_capability` 一致、均真实进入能力、
均不因书写格式被判成缺项。

一条**语义缺项**负例（刻意缺掉一项能力必需的业务语义，其余照抄正例）。
**PASS**：精确 Return 并指名缺的那一项，不因格式误判、也不放行。

判据先冻结正负两例的完整输入原文；负例必须是**真的缺语义**，不是正例改写。

### UAPP-RECOVERY-01｜受控失败后的局部恢复与幂等（AC-09）

在已完成第 1 步的会话上，重复提交同一条反馈两次。

**PASS**：第二次不产生第二行数据（幂等键相同）；系统不声称写了两次；
已成功的组件不重跑；不丢 task/account/cycle/version。

**FAIL**：出现双份事实；或整轮重跑；或把「跑通了」当成「写入发生了」。
