### 4.1 Stage 2 第一次为什么失败，为什么允许重试

```
[models] Server Unavailable Error, HTTPSConnectionPool(host='api.deepseek.com', port=443): Max retries exceeded with url: /chat/completions (Caused by SSLError(SSLError(1, '[SSL: DECRYPTION_FAILED_OR_BAD_RECORD_MAC] decryption failed or bad record mac (_ssl.c:2559)')))
```

| 判据 | 结论 |
|---|---|
| 失败类型 | **TLS 连接中断**（`DECRYPTION_FAILED_OR_BAD_RECORD_MAC`），发生在到 provider 的 HTTPS 上 |
| §五 是否允许重试 | **允许** —— 明确属于「TLS、连接中断」类；只重试了 1 次 |
| 首次失败 Run | **原样保留**（`ad003b64` / `c918ac92`），未覆盖、未删除 |
| 是否重跑了已成功的 Stage 1 | **否** —— Stage 1 产物原样复用 |
| 是否因内容不理想重试 | **否** |
| 是否缩短 Brief / 删减 Skill / 改输出合同 | **否** |

**顺带排除了一个常见成因**：宿主 `eth0` MTU = 1420，容器 MTU = 1420，**两者相同**，所以这次不是 WSL2／Docker 的 MTU 不匹配，是一次真正的瞬时 TLS 中断。（该检查为只读，未修改任何网络或 Docker 配置。）
