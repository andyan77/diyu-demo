## 三、四道确定性闸

写在 PP 子流的 Returns Adapter 里（**确定性代码，无 LLM，纯字符串实现，不 import 任何模块**）。
它们**只判「这份交付块能不能交」，不改模型正文一个字**。

| 闸 | 查什么 |
|---|---|
| 1 | `used_fact_refs[]` 里的编号必须是登记全称；简写、自造、`fact_refs[]` 里不存在的一律不合格 |
| 2 | 交付块出现「已删除／已剔除／审查发现／修正后／原方案／上一版／未核实不得使用」等内部过程语言 |
| 3 | **假绿**：产出声称某句「已删除」，但那句话仍出现在交付块里 |
| 4 | `cta_contract` 为无 CTA 时，交付块出现奖励、领取、关注、私信、购买或预约引导 |

**上线前先拿靶子验过**：用 P05R1 那份出问题的产出当输入，四道闸**全部命中**；
干净样本判 OK；「不得删除边界段」这类禁令句**不被误判成删除声明**。

闸的判定接到 Stage 2：`BLOCKED → chain_status = USER_DELIVERY_BLOCKED_FACT_CHECK`。
**闸的实现只在子流（1 处），父流只透传（0 处）**，父流不代为放行。

### 4.1 第 1 次：崩在我的节点配置缺陷上

`Returns Adapter | failed | Not all output parameters are validated.`

Dify 的 Code 节点要**声明输出参数**。我往返回字典里加了三个键，没在节点声明里登记。
**这是我的缺陷，不是模型质量结果**——那一次根本没产生任何 PP 评判。

**但那一次的模型产出是存在的（47,048 tokens），已从节点执行记录里抢救出来离线复算**：

| 项 | 结果 |
|---|---|
| 四道闸 | **全过**（8 个完整编号、零内部过程语言、零假绿、零 CTA 越界） |
| `mode` | **`PRE`** |

Skill 修订**第一次就生效了**。但 mode 判成了 PRE，它给了三条理由，其中两条指向
**我在 P05 埋的一句提示词缺陷**：manifest 那一节下面写着
「**本节为空**，表示上游没有交来 `realization_manifest`」——**而那句话就贴在 2,700 字 manifest 正文的正下方**。
模型把那句注释读成了「本节确实是空的」。

修法：给 manifest 加明确分隔线，注释改写为「**只看两条线之间有没有内容**」，

### 4.2 第 2 次：同一类错的第二个位置

### 6.2 人工侧：查出一处无依据事实

按规定逐句核验交付块的七类事实性表达。**在发布文案第一句查出一处**：

> 片子里没说的是：单穿那一帧，不是我们**从十几次试穿里**挑出来的「最好看的一次」
> ——是同一段记录里，脱掉外套那一下，连着的。

| 核查项 | 结果 |
|---|---|
| 「十几次／多次试穿／N 次试穿」在全部 7 项输入中的出现次数 | **0** |
| 输入对试穿次数的原话 | 只有「**试穿记录一**」，是单次记录 |
| `BRF-SUHE-001-A04` 登记原文 | 「来自同一段连续记录，**未经过选择性挑取**」——**不含任何数量信息** |
| 模型在 `used_fact_refs[]` 里给这句挂的编号 | `BRF-SUHE-001-A04` |

**模型把「未经选择性挑取」扩写成了「不是从十几次试穿里挑出来的」，凭空造出一个数量。**

**即使是否定句式也不行**：「不是从十几次里挑的」这句话**预设了十几次存在**，
读者读到的就是「他们试了十几次」。这是把一件没发生的事，用否定的外壳送进了发布文案。

### 6.3 这一处最值得记的地方

**它挂着一个真实存在的 `fact_id`，四道闸和两个扫描器全部放行。**

- 闸 1 只查编号**格式**，不查那条事实**是否真的支持这句话**；
- 触发词扫描没有词可触发——句子平实、无夸张词、无引号、无数字断言之外的标记。

这正好印证了规定里那句话：**`used_fact_refs[]` 里写了 `fact_id`，不代表自动通过。**
它是**人逐句读出来的**，不是任何一道自动检查抓到的。

**结论：确定性闸把「格式型」和「自述型」问题堵住了，堵不住「语义型」编造。**
要堵后者，只有两条路：逐句人工核验（本轮就是这么抓到的），或者引入语义比对——
而后者需要模型评判，超出当前边界，本轮不做，列为待裁决。
