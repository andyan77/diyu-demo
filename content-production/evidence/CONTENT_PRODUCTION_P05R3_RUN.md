# 内容生产链 · P05R3 运行记录

> **独立语义事实核验 · 非衰减验证 · 交付收口**

**结论：`SEMANTIC_CHECKER_ACCEPTED_NO_REGRESSION`**

两句话说清这一轮：**语义核验这套东西收下了**——两个探针都对，十条非衰减判据全过。
**但用它跑的那一次内容没通过**——两层检查同时拦下，所以不出 v0.3 用户交付包。
这两件事是分开的：前者是工具验收，后者是这一条片子的质量结论。

---

## 一、这一轮想解决的是哪个问题

P05R2 建了四道确定性闸，在真实运行里拦截成功，十二项自动验收 12/12 全过。
然后人逐句读了一遍交付块，读出一句机器全都放行的话：

> 片子里没说的是：单穿那一帧，不是我们**从十几次试穿里**挑出来的「最好看的一次」

这句话挂着一个真实存在的编号（`BRF-SUHE-001-A04`），用词干净，没有任何内部过程语言，
四道闸和两个扫描器全部放行 —— 因为它们查的是**格式**和**自述**，不是**语义**。
A04 的原文只说「来自同一段连续记录，未经过选择性挑取」，从头到尾没有「十几次」这个数量。
否定句也不能豁免：说「不是从十几次里挑的」，本身就预设了十几次存在。

**这一轮只做一件事**：在 PP 之后加一个只读的语义核验节点，
然后用两个固定探针验它到底有没有用、有没有把原来好用的东西弄坏。
有用且没弄坏 → 收下；否则 → 完整回退，改成人工事实复核后交付，这个问题就此结束。

## 三、这个节点是什么

在通用 Stage 2 里，PP 跑完之后加一个 `Semantic Fact Check` 节点。
**它只读，不写。** 它读完只回答一句话：交付块里被当成已经发生过的事来说的内容，有没有依据。

| 配置 | 值 |
|---|---|
| provider | `langgenius/tongyi/tongyi` |
| model | `qwen3.8-max` |
| mode | `chat` |
| top_p | `0.8` |
| temperature | 不设置 |
| Memory | 关闭 |
| 联网搜索 | 显式关闭（与插件默认值一致，写出来是为了让第三节的约束在 DSL 里可查） |
| 推理与正文分离 | 保留思考模式，正文只取 `</think>` 之后那一段（沿用仓库既有做法） |
| 节点自身失败 | `error_strategy: default-value` —— 不阻断内部产物保存 |

**换 Qwen 只是为了拿一个独立意见**，不改变 DeepSeek V4 Flash 作为内容生产主模型的口径。
PP 依然由 DeepSeek 生成，输入、Prompt、Skill、References、参数一个字没动。

### 它拿得到什么、拿不到什么

| 给它的（4 样） | 不给它的 |
|---|---|
| PP User Delivery Block | PP 的自检结论 |
| 10 条完整 `fact_refs` | `used_fact_refs[]` 的「已核实／已删除」自述 |
| `cta_contract` | `failure_case` |
| `realized_payoff` | 模型推理、其他候选方案、外部知识与联网结果 |

不给自述那一栏是有原因的：**模型说自己核实过，不是证据**。P05R1 那次假绿就是这么来的。

### 它被明确禁止做的事

不评分、不评价创意、不重写内容、不提优化方案、不改标题封面发布文案、不自动调用 PP 重跑。
结构上也做死了：这个节点只有一条出边通向汇总节点，且只被读作 `sem_raw` 一个变量；
交付块的取值路径与改造前逐字相同，它碰不到。

### 它只会让判定更严，不会替谁放行

已有四道闸判 `BLOCKED` 时，语义层判 PASS 也翻不回去；核验节点自己失败时同样翻不回去。
这两条在落盘前用代码逐一执行验证过。

## 四、先跑了一次管路冒烟（如实登记）

正式探针之前跑过一次**合成语料**的冒烟，只为确认三件工程事：模型解析得到、参数被接受、JSON 回得来。
语料是一段和服装完全无关的咖啡店文本，与两个探针没有任何词面重合。
**冒烟结果没有被用来调 Prompt** —— 探针前后 Prompt 的 SHA 完全相同（`sem_sys` = `fdea33ddc866c6ef`，`sem_user` = `98c198030d626c63`），
两个探针跑的是同一份、也是最终落盘的这一份。

## 五、负向探针

**输入**：P05R2 第 4 次的 User Delivery Block（`e0b28add4c5bf785`，1437 字符），10 条 fact_refs，`NO_CTA`，该次的 `realized_payoff`。
**只跑一次。**

| 项 | 值 |
|---|---|
| 节点状态 | `succeeded` |
| 用时 | 329.8 秒 |
| tokens | 19116 |
| `verdict` | **`BLOCK`** |
| 条目数 | 2 |

### 它抓出了什么

**第 1 条**

> 片子里没说的是：单穿那一帧，不是我们从十几次试穿里挑出来的「最好看的一次」——是同一段记录里，脱掉外套那一下，连着的。

**它为什么不成立**：最接近的是 [BRF-SUHE-001-A04]，它只说明用于「单穿比较」的画面来自同一段连续记录、未经过选择性挑取；realized_payoff 也只记录单穿前后同属一段连续记录。材料中没有任何「十几次试穿」或从多次试穿中挑选的记录，这句话多出了「十几次试穿」这一次数／来源前提。

**这句话声称引用的编号**：BRF-SUHE-001-A04

**第 2 条**

> 这一页，留给周宁：哪些问题能在选品阶段提前看出来，哪些必须试过才知道。

**它为什么不成立**：最接近的是 [BRF-SUHE-001-F01] 和 [BRF-SUHE-001-F05]：F01 只说明周宁是商品事实确认人，F05 只说明肩部、袖长、裤长仍需本人试穿。材料没有周宁承接或回答「选品阶段能提前看出什么、必须试过才知道」的记录；realized_payoff 中完成接力宣告的是苏禾，也不能据此补出周宁的人物事实。这句话多出了周宁参与该页／回答的人物安排。

**这句话声称引用的编号**：BRF-SUHE-001-F01、BRF-SUHE-001-F05


**第七节要求的三件事全部达到**：判 BLOCK；抓出的正是含「十几次试穿」那一整句；
理由写明了 `A04` 只支持「未经过选择性挑取」、不支持「存在十几次试穿」。

**第 2 条要如实说：它判偏严了。** 「苏禾向周宁交出问题」这件事，
在冻结的 Content Brief 里逐字写着（「接力关系：苏禾向周宁交出问题」），在 `cs_final` 里也逐字存在——
它不是编的。核验节点看不到它，是因为第三节把输入限死成四样，Content Brief 不在其中。
**账号结构类的陈述落在它的证据范围之外。** 这一条对本次 verdict 没有影响（第 1 条已经足够判 BLOCK），
但它是这个节点的真实边界，写在这里，不藏。

## 七、唯一一次正式运行

输入逐字复用 P05R2 的 FINAL 输入，运行前 19 项逐项核对 SHA 通过，且不含 `FINAL` / `MIXED` 字样。
PP 仍由 DeepSeek V4 Flash（`reasoning_effort=low`）生成，语义核验只在 PP 完成之后读交付块。

| 项 | 值 |
|---|---|
| 父 Run | `4216acf1-4fef-4af1-9670-59eec846803f` |
| 状态 | `succeeded` |
| 用时 | 596.4 秒 |
| tokens | 65720 |
| `pp_mode` | `FINAL` |
| 四道确定性闸 | `BLOCKED` |
| 语义核验 | `BLOCK`（节点状态 `OK`） |
| `chain_status` | **`USER_DELIVERY_BLOCKED_FACT_CHECK`** |
| Artifact | 13184 字符 |
| User Delivery Block | 1519 字符 |

**两层同时拦下了这一次。** 先说清楚各自拦的是什么，不要混为一谈：

**已有的四道确定性闸**：`闸1 fact_id 写成了简写：A02,A03,F03,F04`。
这是格式类问题——`used_fact_refs[]` 里把登记全称写成了简写。
它跟语义核验没有关系；**就算今天不加语义节点，这一次也会被拦住。**
顺带记一笔：P05R2 第 4 次同样的输入下这道闸是过的（9 个全称、零简写），这次没过——
**是 PP 自身的批次波动**，不是语义节点造成的（它跑在 PP 之后，物理上影响不到 PP 怎么写）。

**语义核验**：`BLOCK`，2 条。这 2 条是四道闸看不见的那一类。逐条查证如下。

**第 1 条**

> 原句：结果挺意外：前一天点头的是她，停下来的也是她。 ｜ 不成立的理由：最接近的是 [BRF-SUHE-001-A01] 与 [BRF-SUHE-001-A02]：A01 只登记试穿者在会议场景段落做出点头动作；A02 只登记试穿者在连续生活场景段落出现一次停顿并说「太正式了」。两条事实都没有给出任何日期或「前一天」的时间信息，交付块多出「前一天」这一时间限定。 ｜ 声称引用：无

**第 2 条**

> 原句：同一段记录里，我们脱掉西装，单穿也站得住。 ｜ 不成立的理由：最接近的是 [BRF-SUHE-001-F03]、[BRF-SUHE-001-F04]、[BRF-SUHE-001-A04]。F03 只说明保留西装和阔腿裤、放松衬衫袖口与领口，并比较脱下西装后的单穿效果；F04 只说明同一组合的正式程度可以通过穿法调整；A04 只说明单穿比较画面来自同一段连续记录且未经选择性挑取，并明文规定不得作为「单穿也站得住」这一结论的依据。交付块把「单穿也站得住」写成已发生结果，多出了事实清单未登记的正面结论。 ｜ 声称引用：无

### 我自己逐条回去查了一遍

**第 1 条「前一天」——真编造。**
「前一天／昨天／隔天／第二天」在全部 19 项输入里**命中 0 次**。
而 `F02` 登记的是「会议与接送**连续**场景」——同一段连续记录。
「前一天」不只是没依据，它跟已登记的事实**互相打架**。
这是和 P05R2 那句「十几次试穿」完全同一类的东西：凭空多出一个时间／数量。

**第 2 条「单穿也站得住」——真越界。**
`A04` 的原文明写着：**「不得作为「单穿也站得住」这一结论的依据」**。
而这一次 PP 的 `used_fact_refs[]` 恰恰就把这句话挂在了 `A04` 上。
画面拍到了（manifest 里 S4 有 11 秒全身入画），但「站得住」是一个**判断**，
事实清单里没有任何一条登记过它——`F04` 登记的只是「正式程度可以通过穿法调整」。
这正是 `A04` 那句「不得扩大」当初写下来要防的事。

### 我自己把整份交付块读了一遍

9 个字段逐句读完：**2 处编造全部被抓，0 处编造被放行。**
边界项只有一个 ——「这一页，我留给周宁」，查证后是**有据的**
（冻结 Content Brief 与 `cs_final` 里都逐字存在），放行正确。

值得记的是这一次**没有出现**的东西：P05R1 那类「我们争了半天」的编造内部事件、
那类「说已删除但还在」的假绿、无 CTA 下的奖励诱导、自造的平台字数——一个都没有。
`remaining_blockers` 第 3 条还明确写着平台字数要实测、不自造数字，P05R1 的那处修复仍然生效。

### 所以这一次不出 v0.3 用户交付包

第六节写死了：判 BLOCK 时完整 Artifact 与原 User Delivery Block 原样保留、
**不生成正式用户交付包**、不自动重跑 PP。第十一节允许在验收通过时生成 v0.3，
但那是「允许」，不是「必须」——这一次内容被拦住，就不出包。
**也没有第二次运行**：第八节写明只跑一次；被拦下的是模型的真缺陷，
再摇一次去追绿灯，和人工删句改判是同一种规避。

## 九、这一轮堵住了什么、还堵不住什么

**堵住了**：语义型编造。那句挂着真实 `fact_id`、四道闸与两个扫描器全部放行、
上一轮靠人逐句读才发现的话，这一次是机器判出来的，而且理由指到了具体哪一条事实、缺的是哪一块。
它还顺带找出一处上一轮人工也漏掉的（周宁那一句）。

**堵不住的，要说清楚**：

- 它是一个模型的判断，不是定理。两个探针各只跑一次，是**两个样本**，不是统计结论。
- 它判 PASS 不等于「这份内容可以发布」。它只回答「有没有依据」，不回答好不好、能不能发。
- 前四道确定性闸不能撤。语义层只加在它们后面，永远不替它们放行。
- **它的证据范围只有 4 样输入**，Content Brief 不在其中。所以账号结构、接力关系这类
  「在 Brief 里有据、在 fact_refs 里没有」的陈述，它可能判偏严（负向探针第 2 条就是），
  也可能放过（正式运行里同类句子就放过了）。**这一类它判不稳**，要不要把 Brief 纳进它的证据范围，
  是下一个可以裁决的问题——本轮按第一节不扩范围，只记录。
- 负向探针里那句「十几次试穿」，判据说明里写了一个**结构相同但用词完全无关**的例句（「这不是他第三次改口了」），
  没有把答案原句写进 Prompt —— 否则这个探针就成了送分题，那正是这条链一直在防的假绿。

## 十、本轮明确没有做的事

不新增 Skill、Agent、自动回改循环、评分卡、多级 Reviewer、测试目录、重复工作流、过程总结文档。
不改三份 Skill 与三份 References。不让任何模型评价哪份内容更好。
不声称：真实成片已经验证；内容可以正式发布；已完成生产级部署；跨行业质量已经证明。

**素材仍然是模拟的** —— 本轮验证的是系统行为，不是这条片子本身。
