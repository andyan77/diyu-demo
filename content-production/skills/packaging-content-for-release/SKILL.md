# Publishing & Packaging

把成片变成**能在平台上打得动的发布包**。

**不做**：重写脚本或分镜（要改走「回改建议」）。

---

## mode 是推出来的，不是填的

**不要先问"这条算 PRE 还是 FINAL"。** 按下面三级判据**依次**判断——
**第一级不成立才看第二级，第二级不成立才是第三级。顺序不可颠倒。**

### 第一级 · PRE

满足**任一**条即为 PRE：

- 没有 beat 级 `realization_manifest`；
- `content_origin_mode[]` 里还有一种**计划使用的素材尚不存在**（待拍、待画、待生成、待采集），
  且**没有被正式取消**。

**这一级优先于其他一切 mode 判断。**

### 第二级 · MIXED

已有 beat 级 `realization_manifest`，计划素材均已存在或已正式取消，
**但任一 beat 的覆盖缺口仍处于下列状态之一**：

- 等待补拍
- 等待替代素材
- 等待人工决定
- 处理方式不明确
- 尚未完成承诺降档

**只要还剩一个这样的缺口，整条就是 MIXED。**

### 第三级 · FINAL

已有 beat 级 `realization_manifest`，计划素材均已存在或已正式取消，并且：

- 所有 beat 的画面支撑都是「有」；**或者**
- 存在「没有」或「有，但不够」，但**每一处都已经通过删除、替换或降低承诺完成处置**；
- 没有待补拍、待替换、待人工决定的事项；
- 最终标题、封面、发布文案与 CTA 都已经按 `realized_payoff` 收敛。

### 最容易判错的一条

> **「有，但不够」本身不决定 mode。**
> 决定 mode 的是**这个缺口有没有被处置完** —— 处置完了是 FINAL，还悬着是 MIXED。

同理，**「有覆盖单元」也不等于「已处置」**。一条 beat 可以既在 manifest 里、又留着一个没人拍板的缺口。

**FINAL 的 `uncovered_beats[]` 允许非空**，但其中每一项都必须写出**已经完成的处置结果**
（删掉了什么、换成了什么、承诺降到了哪一档），**不得留下任何 OPEN 项**。
一项写不出处置结果，整条就退回 MIXED。

| mode | 能输出 |
|---|---|
| **FINAL** | **可正式发布**的最终包装 |
| **MIXED** | 已处置的部分正式，仍悬着的缺口相关产出标草案 |
| **PRE** | 全部标注为草案，**不得声称已验证 `realized_payoff`** |

**为什么看 manifest，不看别的**：`script_beats[]` 里的「素材」那一栏是**开拍前写下的计划值**，素材回来之后没有人负责回去改写它。拿计划值判断现实，正是「计划 ≠ 实际」要挡的那件事。manifest 不一样——它按定义只在素材回来、并且对上 beat 之后才存在，**它在不在，本身就是答案。**

**这一条同时解决两个麻烦**：单元的「素材」比 beat 更细时按谁算（不用算，manifest 本来就是 beat 级的）；「待检索」什么时候翻成「已确认」（不用翻，检索完就产出 manifest）。

**混合来源的例外（就是第一级里的第二条，单独讲一遍）**：一条内容同时含"已有素材检索"和"还没拍"两种来源时，**检索先做完是常态**——那一刻已有素材那几条 beat 就有了真实的 manifest。**不要据此往下判 MIXED：整条片子一个镜头都还没拍，任何一部分都不能定稿。**

**规则**：`content_origin_mode[]` 里只要还有一种来源的素材**尚不存在**（待拍、待画、待生成、待采集）且**未被正式取消**，**整条走 PRE**，不看已经检索完了多少。

一句话分辨：**PRE 是"还没拍完"；MIXED 是"拍完了，但还有缺口没人拍板"；FINAL 是"拍完了，缺口也都处置掉了"。** 检索完成度再高也不改变第一级的判断。

**资产级的清单不是 manifest。** 上游只交「拍了 42 分钟」「有 36 张图」，说明它没告诉你哪条 beat 被覆盖——**按"没有 manifest"处理，走 PRE**。回退 Production Director 要 beat 级的，不要自己按分钟数猜。

**"没有新拍"不是走 PRE 的理由。** 已有素材剪辑模式下素材两个月前就存在，检索完、对上 beat 就是真实的 manifest，往下走第二、三级判——一律降级会把包装上限无谓压低。反过来，**"素材名义上有"也不是走 FINAL 的理由**：没检索、没对位，manifest 就不存在。

**MIXED 的处理**：按 manifest **覆盖到的部分**归纳 `realized_payoff`，包装上限取它；未覆盖的部分产出的一切标草案，且**不得作为标题或封面的缺口兑现物**。

**FINAL 模式的第一步不是写标题，是归纳 `realized_payoff`：**

1. 读 **beat 级**的 `realization_manifest`——哪条 beat 由哪段素材覆盖（对位是上游做的，不在这里重做）
2. 逐条比对 `script_beats[]`：**哪些 beat 在 manifest 里没有对应项**——那就是没拍到的
3. 逐条比对 `fact_refs[]`：**哪些事实真有画面支撑，哪些只剩口说**
4. 归纳出 `realized_payoff` = 这条片子**实际兑现了什么**
5. **然后**才开始做包装，上限是第 4 步的结论

这一步由这份 Skill 负责，不需要额外的环节。跳过它直接写标题，等于对着一个还没看过的片子做承诺。

> **为什么**：拿拍摄计划当现实去写标题，等于对一个还不存在的片子做承诺。关键镜头没拍到，标题就变成了标题党——而你到发布那天才发现。

## 输入

**缺了不要卡住，也不要闷头猜。** 对话里被调用就问；工作流里被调用就用默认并在 `assumptions[]` 声明。

| 槽位 | 缺了怎么办 |
|---|---|
| `script_beats[]` ＋ `content_promise` | **无法工作**，回退上游 |
| `realization_manifest` 或 `realization_plan` | 只有 `plan`、没有 beat 级 manifest ＝ **第一级 PRE**。有 manifest 时按三级判据往下判，**不是有 manifest 就 FINAL**。资产级的清单不算 manifest |
| `subject_domain` 行业／赛道 | 由上游原样透传。**决定加载 `references/industry-conditions.md` 的哪一段**——缺了就按通用处理并在 `assumptions[]` 声明，**不要挑一个"最像的"套上去** |
| `expression_subject` 五类之一 | **问**／默认从脚本口吻反推，标为推断。不同类型的"人物一致性"判据不同 |
| `audience_shift` | 从 `content_promise` 反推，声明是推断。**三段共用一个落点** |
| `fact_refs[]` | 无来源的事实**不得写进标题和封面**——标题是承诺，承诺不能建在没有出处的说法上 |
| `platform` | **问**／默认出平台中立母版，不出正式平台包装 |
| `account_positioning` 对标什么类型账号 | 自选并声明，同时给出"换一种定位会怎样" |
| `cta_contract` 有无 CTA、动作是什么 | 默认无 CTA —— **不得自己创造业务动作** |
| `key_frame` 可截图帧 | 从单元清单里挑一个，标为推断 |
| `duration_band` 短（≤60s）／长（>60s） | **问**／默认短档。长档的完播、收藏、"会不会存下来"逻辑与短档完全不同——长档的收藏动机通常来自可复用的信息，短档来自一句能复述的话 |
| `explicit_non_promise[]` | 只读继承。**包装阶段是最容易把承诺加回来的地方**——上游明说不给结论，标题就不能暗示有结论 |
| `constraints[]` | 只读继承。第三方入镜边界同样约束封面与首帧选帧 |
| `content_origin_mode[]` ＋ `fact_refs[]` | 按 type 区别对待，见下 |

## 母版制

**先出一套母版包装，再出平台改写，每一处改动必须写明为了应对该平台的哪个机制。**

没被改的部分＝通用包装能力；被改的部分＝平台知识；改动理由＝判断本身。

**没改的项要写"不变"并说明为什么。** 一项"不变"都没有＝在为改而改；全都"不变"＝没做适配。

平台的具体规格、权重、时长、入口形态**不写在这里**，全部在 `references/platforms.md`，每条带 `as_of` 与来源。**过期时不得用记忆补。**

**三种拿不到的情况，处置不同：**

| 情况 | 怎么办 |
|---|---|
| 平台未锁定 | 只出母版，不出任何平台改写。**这是正常状态，不是缺陷** |
| 平台锁定了，但 `references/platforms.md` 不可得 | **出条件式改写**：「若该平台属于刷到型 → 资源压首帧；若属于点击型 → 资源压封面」。两条分支都写完整，并在 `missing[]` 注明定稿前必须查表。**不要交白卷，也不要凭记忆选一支** |
| 表里有该平台，但条目已过期 | 按上一行处理，并在 `missing[]` 写明过期项 |

自检第 5 条（改了几项／不变几项）在第二三种情况下按**条件式改写**计数，不判为"没做适配"。

**条件式改写只对"分支型"参数有效**（入口形态、封面 vs 首帧的资源分配——它们是两条路，两条都写得完整）。
**对"数值型"参数无效**（单屏字数上限、标题展示长度、图片张数上限——它们是一个数，没有两条分支）。

**数值型拿不到时，不要自己编一个数出来。** 过去这里写的是"给一个保守下限"——那条规则已经作废：
一个自己填的数字，下游读起来和查证过的数字长得一模一样，会被当成平台规则执行。

**正确做法**：置 `platform_spec_status = PLATFORM_SPEC_UNVERIFIED`，
然后**改用定性的制作要求**把这一项写完整，例如：

- 首屏必须完整可读
- 一屏只表达一个意思
- 标题要保证被截断之后核心信息仍在
- **定稿前在目标平台实测一遍**

**不得**产出「标题 ≤15 字」「字幕 ≤12 字」这类自己定的数字。
定性要求不是留空——它同样告诉下游"这一项要做"，只是不假装知道那个数。

若项目方主动选定一个临时工作值，**必须原样写明**：
「本项目临时制作选择，不是平台已核实规则。」——这句话不能省，省了就变成了伪装成规则的数字。

**结构级参数要提前问**（图文的图片张数上限决定 beat 拆几段）——它影响的不是包装而是内容结构。这一项 Creative Script 也读 `references/platforms.md`；到了这里才发现超出上限，是回退上游改结构，不是在这里删图。

## 核心判断

### PP-1 · 标题不是摘要

**摘要让人觉得"我已经知道了"，标题要让人觉得"我还差一点"。**

**候选数由可用的入口类型数决定，不是先定一个数再凑。** 每种可用类型至少出一个，每个标明是哪一种：

| 入口类型 | 承诺的是 |
|---|---|
| `INFORMATION` 信息 | 你会**得到**一条信息 |
| `RESULT` 结果 | 你会**得到**一个结果 |
| `IDENTITY` 身份 | 你会**得到**一个归属 |
| `CONTRADICTION` 矛盾 | 你会**得到**一个矛盾的解 |
| **`SITUATION` 情境** | 你会**看到**一个场景 |
| **`QUOTABLE_LINE` 金句** | 你会**看到**一句话 |

前四类都预设**正文有可带走物**。判据是这个，不是"有没有结论"——**两者会分家**：一条明说不给结论的内容，可以有很实在的可带走物（三个要你自己填的格子、一次改动的完整经过）。这时前四类仍然合法。

**真正不合法的情况是：正文没有任何可带走物。** 这时用前四类构成超额承诺——观众看完发现手上什么都没有。

**怎么判**：把正文能给的东西写成一句「看完你会拿到 ____」。填不出来的，只有后两类合法。

**同义替换不构成新的标题家族。** 三个候选如果入口类型相同，等于只有一个候选。

**所以没有结论的内容只出两个候选是正常的**——可用类型只剩后两类，硬凑第三个必然是同义替换，凑出来反而不合格。**类型有几种，候选就是几个。**

推荐理由**必须指名正文的哪一处**，不得写"更抓人""更有网感"。

**示例**

> ❌ 「初秋通勤六件单品搭配分享」——看完标题就不用看了，是摘要。
> ❌ 三个候选：「通勤六件」「秋季通勤必备六件」「初秋通勤六件推荐」——同义替换，只有一个候选。
> ✅ `CONTRADICTION`「多穿一层就挤，挤的不是衣服」
> `QUOTABLE_LINE`「'上班要正式，接孩子不想太用力'」
> `IDENTITY`「一周开三次会以上的看这条」
> 推荐第一个，理由：**正文第 2 段给出了挤在哪三处，且画面上手真的碰到了那三处**——标题的缺口在正文有对应兑现。
>
> ⚠️ 推荐理由必须指名**输入里真实存在的**兑现处。如果输入只记了"马甲成立与否取决于内搭体积和袖窿空间"（条件句），就不能写成"我劝你别买"（否决句）——那是 CS-7 意义上的编造，而且编在标题上代价最大。

### PP-2 · 标题、封面、首帧不得三处重复

三者关系只能是：**互补｜证明｜分工** —— 明确标出用的是哪一种。

**首帧和封面不是同一件事**，即使某些平台上它们看起来是同一张图。判断依据是**这个平台的用户是怎么遇到你的**：

| 用户遇到你的方式 | 谁承担第一眼 | 封面的作用 |
|---|---|---|
| 刷到，不用点就在播 | **首帧 ＋ 开头几秒** | 低 |
| 必须先点才播 | **封面 ＋ 标题** | 决定生死 |
| 朋友点赞／转发后带出 | 看带出的是首帧还是封面 | 取决于入口形态 |

**哪个平台属于哪一种，查 `references/platforms.md`**（每条带 `as_of` 与来源）。平台入口形态会变，正文不写死具体平台的结论。

封面文字层级：
- 第一行是缺口那句，字号明显大
- 第二行是限定条件（谁看、什么场合），小
- 文字不压脸、不压主体动作
- **行数按缩略图尺寸定**——在实际展示尺寸下读不出来的字，等于没写

**示例**

> ❌ 标题「三层同穿，挤在这三处」＋ 封面大字「挤在三处」＋ 首帧同一画面
> ——三处说同一句话，浪费了两个入口。
> ✅ 标题给**缺口**（是哪三处）｜封面给**情境**（穿着三层的实拍 ＋ 小字"初秋通勤"）｜首帧给**证明**（手停在领口那一处，还没动）

### PP-3 · 包装的承诺上限取实际成片

`single_distribution_promise ≤ realized_payoff`

**不得**为了让包装成立而修改上游的 `content_promise`。发现成片弱于原承诺时：

1. `realized_payoff` 记录实际兑现了什么
2. 包装按 `realized_payoff` 做，不按 `content_promise` 做
3. **如果正文语义必须正式改**，走 `return_to_script`，由 Creative Script 发新版本

**只降标题是不够的。** 正文的开场和主体可能仍在超额承诺——观众看到第 8 秒才发现兑现不了，完播和收藏一起崩。

**PRE 模式下**：`realized_payoff` 尚不存在，包装以 `content_promise` 为上限，**且全部标注为草案**。

> **为什么**：所有内容系统都从脚本写标题。但成片才是观众真正看到的东西——脚本承诺了对比实验，实际只拍到一组，标题写"三组对比"就是骗点击。

### PP-4 · 发布文案是第二个入口，不是标题的展开

- 开头三行必须能**独立成立**——很多人只看到这三行
- **不复制口播稿。** 写片子里没放进去的那一句
- 结尾放一个**能一句话回答的具体问题**，不是"你怎么看"

#### 「片子里没说的是……」这个结构有前置条件

它读起来像在爆料，所以**最容易被用来编一件根本没发生的事**。

**只有同时满足三条才允许使用**：

1. `fact_refs[]` 里**存在**对应的那条事实；
2. 它有**明确的 `fact_id`**；
3. 该事实**确实没有进入成片**（进了成片就不是"没说的"）。

**没有对应 `fact_id`，一律不得生成**：内部争论、内部讨论、投票、表决、
人物的停顿或表情、任何人的原话、以及其他任何"已经发生过"的事件。
**想不出可写的，就不用这个结构** —— 用不上它不算缺陷，编一件事出来才是。

**示例**（占位符形式，不提供可直接套写的情节）

> ❌ 「今天给大家分享初秋通勤的六件单品，分别是……」——口播稿的复述。
>
> ❌ 「片子里没说的是：那一件我们内部争了很久。」
> ——`fact_refs[]` 里没有任何一条登记过"内部争论"这件事。**这句是凭空造出来的。**
> 它之所以危险，是因为读起来完全像真的：没有夸张词、没有数字、没有引号，
> 一条只查触发词的扫描器对它是瞎的。
>
> ✅ 「片子里没说的是：〈`FACT-ID-X` 登记的那条事实，且它确实没剪进成片〉。」
> 「〈同一条事实里被登记下来的取舍或条件〉。」
> 「〈最终选择，以及它依据的是哪条已登记事实〉。」
> 「〈一个能一句话回答的具体问题〉」
>
> 写这四行时，**每一行都要能在 `used_fact_refs[]` 里挂上 `fact_id`**。挂不上的那行删掉。

### PP-5 · 评论区是设计出来的，不是等来的

- **第一条自己写**，写一条**能被追问的**，不是"感谢支持"
- 预埋 2 个可能被问到的问题，先准备好答案
- 作者回复要**给新信息**

**先分清主场还是客场：**

| | 主场 | 客场 |
|---|---|---|
| 情况 | 议题由这条内容自己设定 | 内容是**从别处的评论／提问长出来的** |
| 置顶落点 | 一处：新内容下 | **两处**：新内容下，**以及原提问所在的那条下面** |
| 已有讨论 | 无 | 已经存在，且**你可能不知道里面说了什么**——不得引用、概括或形容它的内容 |

**准备一个诚实的"我答不出"。** 有些内容最可能被问的恰恰是作者答不出的（"孩子后来知道了吗""那我到底该带多厚的睡袋"）。这种问题**不得代答**——代答就是编造。准备的是一句诚实的边界说明，加上你确实能给的那部分。

**示例**

> ❌ 置顶「谢谢大家支持，有问题欢迎留言～」
> ✅ 置顶「被否掉的那件是马甲。想知道为什么可以问我。」
> 预埋问答：① 马甲到底值不值得买 → "取决于你内搭的体积和袖窿空间" ② 六件的价格 → 逐件报，不含糊
> ✅ 诚实边界式：「那我该带多厚的睡袋？」→「我这只是充绒 400g、舒适温标 -2℃。**这是我的参数，不是你的答案**——温标写在标签上，你那晚的风和温差没写在任何标签上。」

### 作者转发语

入口形态含**社交带出型**的平台上（哪些平台，查 `references/platforms.md` 第一节），**作者自己转发时说的那句话，比标题更早被读到**——它是内容进入熟人流的第一句。其余平台这一项可选。

写一句，规则同 PP-1：不是摘要，且不能承诺正文没有的东西。

## 发布前成片检查

五条，逐条看，不是流程：

1. **静音播放一遍**——看得懂吗？看不懂的话，在无声环境下刷到就是划走
2. **只看首帧 1 秒**——知道这是关于什么的吗？
3. **只看封面＋标题**——想点吗？是因为哪一句？
4. **看完之后**——我会存下来吗？存来干什么用？
   **答"不会"也是合格答案。** 有些内容天生不是收藏型（情绪、共鸣、一次性的场景）。这一条问的是"知不知道自己靠什么留存"，不是"必须能被收藏"——**不要为了让这一条通过而反向修改内容**。答"不会"时，第 5 条就是主判据。
5. **转发想象**——我会转给谁？转的时候我说一句什么？说不出来就不要指望转发
   **入口形态含社交带出型的平台上，这是主判据。** 转发一条给结论的内容，转发者背书的是一个**立场**（成本高）；转发一条没有结论的，背书的是一个**承认**（成本低，但暴露度高）。两者的转发驱动完全不同。

## 非视频形态的字段映射

**不适用的字段要写 `NOT_APPLICABLE` 并说明**，不要留空——留空下游读成"忘了做"。

| 字段 | 图文 | 纯音频 | 纯文字 |
|---|---|---|---|
| `cover` | **首图**——它同时是封面和首帧 | 静态封面，唯一视觉入口 | 无图时**首行文字**承担全部 |
| `first_frame` | 与 `cover` 合一。**PP-2 的"三处不重复"变成两处**（标题 ＋ 首图），空出来的第三个位置由**首行文字**补上，不是少做一项 | NOT_APPLICABLE | NOT_APPLICABLE |
| `caption_rules` | 换成**图内文字规则**：每张图上几行、放在哪、会不会被下一张的翻页控件遮住 | 换成**章节点／文字稿**：听众靠什么定位到某一段 | NOT_APPLICABLE |
| `sound_placement` | **先查平台**：图文形态在部分平台带音轨。不带＝NOT_APPLICABLE；带＝按「它承担什么」填，且**揭晓页不得加音效**（那会把读者刚做完的一次判断变成节目效果）。<br>**「没有现场声」不等于「没有音轨」** | **它是主体不是配角**——进出点定的是内容结构，不是氛围 | NOT_APPLICABLE |
| `duration_band` | **换成"翻几屏"**：短＝一屏读完的量，长＝要连续翻的量。<br>它不是可跳过的字段——**检查④（会不会存下来）和 PP-1 的候选取向都挂在它上面**。图文按可复看的信息型内容处理时取长档，并在 `assumptions[]` 写明这是类比不是换算 | 按**听完要多久**填，判据不变 | 换成**读完要多久** |
| `key_frame` | **不一定是首图。** 首图是**入口**（要留悬念），可截图帧是**转发件**（要能独立成立）——图文里这两者最容易分离，仍按原判据选：单独发给一个没看过全文的人，他看得懂吗 | 静态封面（纯音频唯一的可截图物） | 可截图的**那一段文字** |
| 检查①（静音看一遍） | 换成**只看图不看字**，读得懂吗。<br>**允许答"部分不合格"**——叠字在图文里往往是主通道，恒不合格是正常的。修补必须落在**不承载表达的版式元件**上（序号、进度、位置标识），**不得靠加文案**——用主通道补主通道，加完还是关掉就看不懂 | 换成**只听不看**，跟得上吗 | NOT_APPLICABLE |
| 检查②（只看首帧 1 秒） | 只看首图 | 只看标题 ＋ 封面 | 只看首行 |
| 检查③④⑤（封面＋标题／会不会存／会转给谁） | 照常 | 照常 | 照常 |
| 标题、发布文案、评论区、转发语 | **全部照常** | 照常 | 照常 |

**这张表的重点是最后两行**：换所指的只有画面相关的几项，PP-1 到 PP-5 的判断本身不因形态改变。**不要因为"这次是图文"就整块跳过包装。**

## 关于数据

公开可核验的数据（播放、点赞、收藏比）可作为**现象参考**引用，标明来源与时间。

**但不得把播放量直接当成创意质量。** 高播放可能来自投放、蹭热点、账号存量；低播放可能只是发布时间不对。**数据用来提问，不用来下结论。**

## 自检

1. 标题是摘要还是缺口？——摘要就重写
2. 候选覆盖了几种入口类型？——**只有一种等于只有一个候选**；类型数与候选数对得上吗
3. 封面和标题是不是在说同一件事？——是就浪费了一半
4. 刷到型平台的首帧和点击型平台的封面，是同一张吗？——是就说明没做平台适配
5. 平台改写里标了几项"不变"？——一项没有＝为改而改；全都不变＝没做适配
6. 发布文案开头三行单独拿出来，成立吗？
6b. **逐句比对发布文案正文和逐字稿**——有几句是口播稿的搬运？**一句都不该有**。自己声称"没有复述"不算数，要真的比对过
7. mode 是**按三级判据依次**推出来的，还是拍脑袋填的？判 FINAL 之前，`uncovered_beats[]` 里每一项**都写出已完成的处置结果**了吗——还剩一项 OPEN 就该是 MIXED。PRE／MIXED 里仍悬着的那部分产出，有没有全部标注为草案？
8. FINAL 模式下，`realized_payoff` 是从 **beat 级** manifest 归纳出来的，还是拿一句"拍了 42 分钟"当依据？
8b. `used_fact_refs[]` 里，`realized_payoff`／推荐标题／封面／发布文案／评论区事实陈述，
    **五处都回指到具体 `fact_id` 了吗**？有没有哪一句是事实性表达却挂不上任何 `fact_id`——
    挂不上就不能留在定稿里。
9. `explicit_non_promise[]` 里的东西，标题、封面、置顶评论有没有把它悄悄承诺回来？
9b. 上游 `constraints[]` 里的禁令，**封面和首帧的选帧**守住了吗？——第三方入镜、未成年人不露正脸这类禁令，最容易在封面上破功
10. 平台规格拿不到时，出的是**条件式改写**（分支型）与**定性制作要求**（数值型），
    还是白卷、或者一个自己编的数字？`platform_spec_status` 标了吗？
