## 合法等价兑现证据与直达

> 本节是 M4 新增。它只回答「兑现证据可以从哪来」，**不改动下一节的三级 mode 判据一个字**。

### 本 Skill 要的是业务语义，不是上游文件

**本 Skill 不要求上游必须物理产出 `cs_final` 与 `pd_final`。** 要求的是下面这些**业务语义**齐不齐：

- 准确的内容正文 / 脚本节拍 / 等价的成片内容说明；
- 内容承诺与明确不承诺；
- 事实及其来源；
- 表达主体或账号包装定位；
- CTA 目标 / 授权 / 承接边界；
- 素材发布权限。

这些语义齐了就能开工，不管它们装在哪个文件里、由谁产生。**来源、确认状态、权限、作用域、时效与证据等级必须原样保留**——语义等价不等于证据等价，也不等于权限等价。

### 合法的等价兑现证据有四类

判据只有一条：**它能不能按 beat（或等价内容单元）逐条回答「这条的事实有多少画面／内容支撑」。** 答得出就是兑现证据，答不出就不是。

| 等价输入 | 成立条件 |
|---|---|
| ① 已有成片 ＋ 成片内容说明 | 能逐条对应到内容单元，并标明每个单元的支撑状态（有 / 没有 / 有，但不够） |
| ② 用户提供的 beat 兑现清单 | 含**内容单元**、**素材出处**（起止时间码，或第几张）、**支撑程度**、**缺口处置** |
| ③ 已有素材剪辑，且检索已完成并对上单元 | 检索完成且对上单元 ＝ 真实 manifest，可以往下走第二、三级判——**「没有新拍」不是走 PRE 的理由** |
| ④ 图文 / 纯音频等非视频成品 | 按对应载体的单元定义（第几张、第几段、第几屏）逐条回答同样两个问题 |

### 不成立的情况

**只给资产级数量的，不成立。** 「拍了 42 分钟」「有 36 张图」——它没告诉你哪条 beat 被覆盖。

处置：**按「没有 manifest」处理，走 PRE**，同时**回退索取单元级的**，**不自行按分钟数或张数猜**。猜出来的覆盖率读起来和真的一模一样，下游会当成已核实的兑现执行。

### 硬禁：有合法成片时强制补跑 CS 或 PD

**本 Skill 不调用、不请求、不假设任何上游组件被运行过。**

- 手上已有合法成片或合法等价兑现证据时，**不得**以「流程上应该先有 `cs_final`」「按规范要先出 `pd_final`」为由要求补跑 Creative Script 或 Production Director；
- **不得**暗中替上游把缺的产物补出来（那等于自己写脚本、自己写分镜，越过本 Skill 的停止边界）；
- 缺的是**语义**时，向提供方索取那一项语义；缺的**不是**语义而只是文件时，**不构成阻断**。

**跳过物理组件只表示等价输入已经满足。** 它不降低事实纪律、权限约束、风险约束，也不降低本次任务必要的专业质量——下面每一条判据照常执行。

### 判据不变的声明

三级 mode 判据、`realized_payoff` 的归纳步骤、「有但不够」的处理、`uncovered_beats[]` 的 OPEN 禁令、资产级清单不算 manifest —— **与源 Skill 完全一致**。本节改的是「兑现证据从哪来」，**不是「怎么判 mode」**。下一节读到「manifest」时，一律理解为「beat 级 `realization_manifest`，**或**本节四类合法等价兑现证据之一」。

## mode 是推出来的，不是填的

**不要先问"这条算 PRE 还是 FINAL"。** 按下面三级判据**依次**判断——
**第一级不成立才看第二级，第二级不成立才是第三级。顺序不可颠倒。**

### 第一级 · PRE

满足**任一**条即为 PRE：

- 没有 beat 级 `realization_manifest`；
- `content_origin_mode[]` 里还有一种**计划使用的素材尚不存在**（待拍、待画、待生成、待采集），
  且**没有被正式取消**。

**这一级优先于其他一切 mode 判断。**

### 第二级 · MIXED

已有 beat 级 `realization_manifest`，计划素材均已存在或已正式取消，
**但任一 beat 的覆盖缺口仍处于下列状态之一**：

- 等待补拍
- 等待替代素材
- 等待人工决定
- 处理方式不明确
- 尚未完成承诺降档

**只要还剩一个这样的缺口，整条就是 MIXED。**

### 第三级 · FINAL

已有 beat 级 `realization_manifest`，计划素材均已存在或已正式取消，并且：

- 所有 beat 的画面支撑都是「有」；**或者**
- 存在「没有」或「有，但不够」，但**每一处都已经通过删除、替换或降低承诺完成处置**；
- 没有待补拍、待替换、待人工决定的事项；
- 最终标题、封面、发布文案与 CTA 都已经按 `realized_payoff` 收敛。

### 最容易判错的一条

> **「有，但不够」本身不决定 mode。**
> 决定 mode 的是**这个缺口有没有被处置完** —— 处置完了是 FINAL，还悬着是 MIXED。

同理，**「有覆盖单元」也不等于「已处置」**。一条 beat 可以既在 manifest 里、又留着一个没人拍板的缺口。

**FINAL 的 `uncovered_beats[]` 允许非空**，但其中每一项都必须写出**已经完成的处置结果**
（删掉了什么、换成了什么、承诺降到了哪一档），**不得留下任何 OPEN 项**。
一项写不出处置结果，整条就退回 MIXED。

| mode | 能输出 |
|---|---|
| **FINAL** | **可正式发布**的最终包装 |
| **MIXED** | 已处置的部分正式，仍悬着的缺口相关产出标草案 |
| **PRE** | 全部标注为草案，**不得声称已验证 `realized_payoff`** |

**为什么看 manifest，不看别的**：`script_beats[]` 里的「素材」那一栏是**开拍前写下的计划值**，素材回来之后没有人负责回去改写它。拿计划值判断现实，正是「计划 ≠ 实际」要挡的那件事。manifest 不一样——它按定义只在素材回来、并且对上 beat 之后才存在，**它在不在，本身就是答案。**

**这一条同时解决两个麻烦**：单元的「素材」比 beat 更细时按谁算（不用算，manifest 本来就是 beat 级的）；「待检索」什么时候翻成「已确认」（不用翻，检索完就产出 manifest）。

**混合来源的例外（就是第一级里的第二条，单独讲一遍）**：一条内容同时含"已有素材检索"和"还没拍"两种来源时，**检索先做完是常态**——那一刻已有素材那几条 beat 就有了真实的 manifest。**不要据此往下判 MIXED：整条片子一个镜头都还没拍，任何一部分都不能定稿。**

**规则**：`content_origin_mode[]` 里只要还有一种来源的素材**尚不存在**（待拍、待画、待生成、待采集）且**未被正式取消**，**整条走 PRE**，不看已经检索完了多少。

一句话分辨：**PRE 是"还没拍完"；MIXED 是"拍完了，但还有缺口没人拍板"；FINAL 是"拍完了，缺口也都处置掉了"。** 检索完成度再高也不改变第一级的判断。

**资产级的清单不是 manifest。** 上游只交「拍了 42 分钟」「有 36 张图」，说明它没告诉你哪条 beat 被覆盖——**按"没有 manifest"处理，走 PRE**。回退 Production Director 要 beat 级的，不要自己按分钟数猜。

**"没有新拍"不是走 PRE 的理由。** 已有素材剪辑模式下素材两个月前就存在，检索完、对上 beat 就是真实的 manifest，往下走第二、三级判——一律降级会把包装上限无谓压低。反过来，**"素材名义上有"也不是走 FINAL 的理由**：没检索、没对位，manifest 就不存在。

**MIXED 的处理**：按 manifest **覆盖到的部分**归纳 `realized_payoff`，包装上限取它；未覆盖的部分产出的一切标草案，且**不得作为标题或封面的缺口兑现物**。

**FINAL 模式的第一步不是写标题，是归纳 `realized_payoff`：**

1. 读 **beat 级**的 `realization_manifest`——哪条 beat 由哪段素材覆盖（对位是上游做的，不在这里重做）
2. 逐条比对 `script_beats[]`：**哪些 beat 在 manifest 里没有对应项**——那就是没拍到的
3. 逐条比对 `fact_refs[]`：**哪些事实真有画面支撑，哪些只剩口说**
4. 归纳出 `realized_payoff` = 这条片子**实际兑现了什么**
5. **然后**才开始做包装，上限是第 4 步的结论

这一步由这份 Skill 负责，不需要额外的环节。跳过它直接写标题，等于对着一个还没看过的片子做承诺。

> **为什么**：拿拍摄计划当现实去写标题，等于对一个还不存在的片子做承诺。关键镜头没拍到，标题就变成了标题党——而你到发布那天才发现。

## 与统一能力接缝的对接

> 本节是 M4 新增。它写的是本 Skill 在能力链里的位置，不改任何包装判据。

### 独有输入、独有输出、独有停止边界

| | 内容 |
|---|---|
| **独有输入** | 兑现证据（beat 级 manifest **或**合法等价兑现证据） |
| **独有输出** | 推导出的 `mode` ＋ `realized_payoff` ＋ 母版包 ＋ 平台适配 ＋ `used_fact_refs[]` |
| **独有停止边界** | **不重写脚本或分镜** |

这三项是本 Skill 不可被别的能力顶替的部分。反过来也一样：**别的能力的产出不能拿来当包装用**——把它们的输出换个名字塞进这里，下游读到的就不是包装。

停止边界要当真：需要改正文语义的，走 Return，**不在这里改**。

### 只读继承的两项

- **`objective.goal_family`（本次任务的目标族）只读继承。** 起号、吸粉、流量、GMV、线索、到店都是合法目标，**不得**在包装阶段被静默改写成「长期价值表达」；反过来，长期价值目标也不得被改写成流量打法。无权改目标时**只做局部 Return**，不静默改写。
  目标可以改变钩子强度、节奏、密度与 CTA 方向；**目标本身不授权高风险表达**。
- **`explicit_non_promise[]` 只读继承。** **包装阶段是最容易把承诺加回来的地方**——上游明说不给结论，标题、封面、置顶评论、转发语、发布文案就都不能暗示有结论。这一条在自检第 9 条复查。

### CTA 三级接缝

| 级别 | 范围 | 条件 |
|---|---|---|
| 低风险互动 | 关注、评论、收藏 | 按目标与表达裁量即可提出，**不要求用户另填 CTA 表单** |
| 经营承接 | 商品点击、咨询、线索、到店、购买引导 | 需要**对应经营目标 ＋ 有效承接路径 ＋ 事实依据**，三者缺一不可 |
| 高风险 | 站外导流、价格优惠、强购买承诺等 | 需要**明确授权** |

硬规则：

- **目标本身不自动授权高风险 CTA。** 流量、吸粉、GMV 目标 ≠ 授权激进、争议或高风险表达。
- CTA **不得编造**商品事实、价格、优惠、库存、承接能力或经营承诺。
- `cta_contract` 可取 `KNOWN_BUT_NOT_AUTHORIZED` —— 知道存在业务动作但本条未获授权。**这是权限不全，不是信息不全**：不要把它当成"再问一次就能补上"的缺口。
- `cta_contract = 无 CTA` 时，**整份产出**（含评论区与转发语）不得出现奖励、领取、关注交换、私信、到店、预约、购买、下单或咨询引导——详见「无 CTA 时评论区能做什么」。

**面向用户时用自然语言表达具体的行动方向，不暴露内部分级术语。** 交付块里写「可以在评论区问一句『你那件是几分袖』」，**不写**「本条 CTA 级别为 `LOW_RISK_INTERACTION`」。内部状态码、级别名、`KNOWN_BUT_NOT_AUTHORIZED` 这类词留在完整 Artifact 里。

### CTA 权威顺序

> 本节是 b1 新增。它规定上面那张三级表**什么时候适用**，不改表里任何一行的内容。

**权威顺序（高在前，低者不得放宽高者）：**

```
cta_contract 的用户／上游自然语言原文
  >
已确认的 Content Brief 与任务边界
  >
cta_level
  >
本 Skill 的默认互动方法
```

**1. 上游闭合表达一旦出现，整份包装闭合。**
上游 `cta_contract` 里出现「只保留内容本身」「不做任何引导」「不做关注、评论、收藏」
或**其它等价的明确闭合表达**时，**整份产出**——标题、封面、首帧、发布文案、评论区置顶、
预埋问答、作者转发语、平台变体，一处不漏——**不得要求受众**：

```
购买 · 下单 · 到店 · 预约 · 咨询 · 私信 · 领取
关注 · 评论 · 回复 · 收藏 · 转发 · 分享 · 点赞 · 参与话题
```

**2. 不得用「低风险互动」放宽上游更严格的边界。**
三级表里的「低风险互动」是**上游没有给出更严格边界时**的默认裁量空间。
上游已经闭合时，它**不再适用**——低风险不是豁免。

**同样不得自造豁免类目。** 给某一处表达安一个新名目，说它属于某种"轻的""温和的"
"不算转化的"类别，因此不受边界约束——**这个类别不在任何冻结判据里，叫什么都一样。**
自造类目不产生豁免，只是把越界写成了合规。
边界只能由有权者改版，**执行方不得在产出里把它改写成更宽的一条**。
把上游原文压缩、改述、只挑其中一半来做合规自检——同样是改写。
**自检的对照物必须是 `cta_contract` 的原文本身，不是你对它的复述。**

**3. 内容内部的问题不是 CTA。**
用来表达主题的自问、反问、判断问题——「这件到底该不该买」「我该怎么判断」——
写在口播、文案正文或文字卡里，是**内容本身**，不构成 CTA。

界线只有一条：**这句话是不是在要求受众去做一个动作**（回答、留言、互动、点击、到店……）。

| | 是不是 CTA |
|---|---|
| 「这件到底该不该买？」（正文里的设问，随后自己给出判断） | 不是 |
| 「你会怎么选？」「你先问自己哪个问题？」（句末指向受众，等一个回答） | **是** |
| 「评论区设计：置顶一条能被追问的」（为引出留言而设计的整段） | **是** |

**4. 本节不删除低风险互动能力。**
上游**未明确禁止**，且目标、事实、权限允许时，仍按上面的三级表照常处理——
评论区照常设计，置顶照常写。**收紧只发生在上游已经闭合的那些条上。**

## 母版制

**先出一套母版包装，再出平台改写，每一处改动必须写明为了应对该平台的哪个机制。**

没被改的部分＝通用包装能力；被改的部分＝平台知识；改动理由＝判断本身。

**没改的项要写"不变"并说明为什么。** 一项"不变"都没有＝在为改而改；全都"不变"＝没做适配。

平台的具体规格、权重、时长、入口形态**不写在这里**，全部在 `references/platforms.md`，每条带 `as_of` 与来源。**过期时不得用记忆补。**

**三种拿不到的情况，处置不同：**

| 情况 | 怎么办 |
|---|---|
| 平台未锁定 | 只出母版，不出任何平台改写。**这是正常状态，不是缺陷** |
| 平台锁定了，但 `references/platforms.md` 不可得 | **出条件式改写**：「若该平台属于刷到型 → 资源压首帧；若属于点击型 → 资源压封面」。两条分支都写完整，并在 `missing[]` 注明定稿前必须查表。**不要交白卷，也不要凭记忆选一支** |
| 表里有该平台，但条目已过期 | 按上一行处理，并在 `missing[]` 写明过期项 |

自检第 5 条（改了几项／不变几项）在第二三种情况下按**条件式改写**计数，不判为"没做适配"。

**条件式改写只对"分支型"参数有效**（入口形态、封面 vs 首帧的资源分配——它们是两条路，两条都写得完整）。
**对"数值型"参数无效**（单屏字数上限、标题展示长度、图片张数上限——它们是一个数，没有两条分支）。

**数值型拿不到时，不要自己编一个数出来。** 过去这里写的是"给一个保守下限"——那条规则已经作废：
一个自己填的数字，下游读起来和查证过的数字长得一模一样，会被当成平台规则执行。

**正确做法**：置 `platform_spec_status = PLATFORM_SPEC_UNVERIFIED`，
然后**改用定性的制作要求**把这一项写完整，例如：

- 首屏必须完整可读
- 一屏只表达一个意思
- 标题要保证被截断之后核心信息仍在
- **定稿前在目标平台实测一遍**

**不得**产出「标题 ≤15 字」「字幕 ≤12 字」这类自己定的数字。
定性要求不是留空——它同样告诉下游"这一项要做"，只是不假装知道那个数。

若项目方主动选定一个临时工作值，**必须原样写明**：
「本项目临时制作选择，不是平台已核实规则。」——这句话不能省，省了就变成了伪装成规则的数字。

**结构级参数要提前问**（图文的图片张数上限决定 beat 拆几段）——它影响的不是包装而是内容结构。这一项 Creative Script 也读 `references/platforms.md`；到了这里才发现超出上限，是回退上游改结构，不是在这里删图。

## 核心判断

### PP-1 · 标题不是摘要

**摘要让人觉得"我已经知道了"，标题要让人觉得"我还差一点"。**

**候选数由可用的入口类型数决定，不是先定一个数再凑。** 每种可用类型至少出一个，每个标明是哪一种：

| 入口类型 | 承诺的是 |
|---|---|
| `INFORMATION` 信息 | 你会**得到**一条信息 |
| `RESULT` 结果 | 你会**得到**一个结果 |
| `IDENTITY` 身份 | 你会**得到**一个归属 |
| `CONTRADICTION` 矛盾 | 你会**得到**一个矛盾的解 |
| **`SITUATION` 情境** | 你会**看到**一个场景 |
| **`QUOTABLE_LINE` 金句** | 你会**看到**一句话 |

前四类都预设**正文有可带走物**。判据是这个，不是"有没有结论"——**两者会分家**：一条明说不给结论的内容，可以有很实在的可带走物（三个要你自己填的格子、一次改动的完整经过）。这时前四类仍然合法。

**真正不合法的情况是：正文没有任何可带走物。** 这时用前四类构成超额承诺——观众看完发现手上什么都没有。

**怎么判**：把正文能给的东西写成一句「看完你会拿到 ____」。填不出来的，只有后两类合法。

**同义替换不构成新的标题家族。** 三个候选如果入口类型相同，等于只有一个候选。

**所以没有结论的内容只出两个候选是正常的**——可用类型只剩后两类，硬凑第三个必然是同义替换，凑出来反而不合格。**类型有几种，候选就是几个。**

推荐理由**必须指名正文的哪一处**，不得写"更抓人""更有网感"。

**示例**

> ❌ 「初秋通勤六件单品搭配分享」——看完标题就不用看了，是摘要。
> ❌ 三个候选：「通勤六件」「秋季通勤必备六件」「初秋通勤六件推荐」——同义替换，只有一个候选。
> ✅ `CONTRADICTION`「多穿一层就挤，挤的不是衣服」
> `QUOTABLE_LINE`「'上班要正式，接孩子不想太用力'」
> `IDENTITY`「一周开三次会以上的看这条」
> 推荐第一个，理由：**正文第 2 段给出了挤在哪三处，且画面上手真的碰到了那三处**——标题的缺口在正文有对应兑现。
>
> ⚠️ 推荐理由必须指名**输入里真实存在的**兑现处。如果输入只记了"马甲成立与否取决于内搭体积和袖窿空间"（条件句），就不能写成"我劝你别买"（否决句）——那是 CS-7 意义上的编造，而且编在标题上代价最大。

---

### PP-2 · 标题、封面、首帧不得三处重复

三者关系只能是：**互补｜证明｜分工** —— 明确标出用的是哪一种。

**首帧和封面不是同一件事**，即使某些平台上它们看起来是同一张图。判断依据是**这个平台的用户是怎么遇到你的**：

| 用户遇到你的方式 | 谁承担第一眼 | 封面的作用 |
|---|---|---|
| 刷到，不用点就在播 | **首帧 ＋ 开头几秒** | 低 |
| 必须先点才播 | **封面 ＋ 标题** | 决定生死 |
| 朋友点赞／转发后带出 | 看带出的是首帧还是封面 | 取决于入口形态 |

**哪个平台属于哪一种，查 `references/platforms.md`**（每条带 `as_of` 与来源）。平台入口形态会变，正文不写死具体平台的结论。

封面文字层级：
- 第一行是缺口那句，字号明显大
- 第二行是限定条件（谁看、什么场合），小
- 文字不压脸、不压主体动作
- **行数按缩略图尺寸定**——在实际展示尺寸下读不出来的字，等于没写

**示例**

> ❌ 标题「三层同穿，挤在这三处」＋ 封面大字「挤在三处」＋ 首帧同一画面
> ——三处说同一句话，浪费了两个入口。
> ✅ 标题给**缺口**（是哪三处）｜封面给**情境**（穿着三层的实拍 ＋ 小字"初秋通勤"）｜首帧给**证明**（手停在领口那一处，还没动）

### PP-3 · 包装的承诺上限取实际成片

`single_distribution_promise ≤ realized_payoff`

**不得**为了让包装成立而修改上游的 `content_promise`。发现成片弱于原承诺时：

1. `realized_payoff` 记录实际兑现了什么
2. 包装按 `realized_payoff` 做，不按 `content_promise` 做
3. **如果正文语义必须正式改**，走 `return_to_script`，由 Creative Script 发新版本

**只降标题是不够的。** 正文的开场和主体可能仍在超额承诺——观众看到第 8 秒才发现兑现不了，完播和收藏一起崩。

**PRE 模式下**：`realized_payoff` 尚不存在，包装以 `content_promise` 为上限，**且全部标注为草案**。

> **为什么**：所有内容系统都从脚本写标题。但成片才是观众真正看到的东西——脚本承诺了对比实验，实际只拍到一组，标题写"三组对比"就是骗点击。

---

### PP-4 · 发布文案是第二个入口，不是标题的展开

- 开头三行必须能**独立成立**——很多人只看到这三行
- **不复制口播稿。** 写片子里没放进去的那一句
- 结尾放一个**能一句话回答的具体问题**，不是"你怎么看"

#### 「片子里没说的是……」这个结构有前置条件

它读起来像在爆料，所以**最容易被用来编一件根本没发生的事**。

**只有同时满足三条才允许使用**：

1. `fact_refs[]` 里**存在**对应的那条事实；
2. 它有**明确的 `fact_id`**；
3. 该事实**确实没有进入成片**（进了成片就不是"没说的"）。

**没有对应 `fact_id`，一律不得生成**：内部争论、内部讨论、投票、表决、
人物的停顿或表情、任何人的原话、以及其他任何"已经发生过"的事件。
**想不出可写的，就不用这个结构** —— 用不上它不算缺陷，编一件事出来才是。

**示例**（占位符形式，不提供可直接套写的情节）

> ❌ 「今天给大家分享初秋通勤的六件单品，分别是……」——口播稿的复述。
>
> ❌ 「片子里没说的是：那一件我们内部争了很久。」
> ——`fact_refs[]` 里没有任何一条登记过"内部争论"这件事。**这句是凭空造出来的。**
> 它之所以危险，是因为读起来完全像真的：没有夸张词、没有数字、没有引号，
> 一条只查触发词的扫描器对它是瞎的。
>
> ✅ 「片子里没说的是：〈`FACT-ID-X` 登记的那条事实，且它确实没剪进成片〉。」
> 「〈同一条事实里被登记下来的取舍或条件〉。」
> 「〈最终选择，以及它依据的是哪条已登记事实〉。」
> 「〈一个能一句话回答的具体问题〉」
>
> 写这四行时，**每一行都要能在 `used_fact_refs[]` 里挂上 `fact_id`**。挂不上的那行删掉。

### PP-5 · 评论区是设计出来的，不是等来的

- **第一条自己写**，写一条**能被追问的**，不是"感谢支持"
- 预埋 2 个可能被问到的问题，先准备好答案
- 作者回复要**给新信息**

**先分清主场还是客场：**

| | 主场 | 客场 |
|---|---|---|
| 情况 | 议题由这条内容自己设定 | 内容是**从别处的评论／提问长出来的** |
| 置顶落点 | 一处：新内容下 | **两处**：新内容下，**以及原提问所在的那条下面** |
| 已有讨论 | 无 | 已经存在，且**你可能不知道里面说了什么**——不得引用、概括或形容它的内容 |

**准备一个诚实的"我答不出"。** 有些内容最可能被问的恰恰是作者答不出的（"孩子后来知道了吗""那我到底该带多厚的睡袋"）。这种问题**不得代答**——代答就是编造。准备的是一句诚实的边界说明，加上你确实能给的那部分。

**示例**

> ❌ 置顶「谢谢大家支持，有问题欢迎留言～」
> ✅ 置顶「被否掉的那件是马甲。想知道为什么可以问我。」
> 预埋问答：① 马甲到底值不值得买 → "取决于你内搭的体积和袖窿空间" ② 六件的价格 → 逐件报，不含糊
> ✅ 诚实边界式：「那我该带多厚的睡袋？」→「我这只是充绒 400g、舒适温标 -2℃。**这是我的参数，不是你的答案**——温标写在标签上，你那晚的风和温差没写在任何标签上。」

### 无 CTA 时，评论区能做什么、不能做什么

`cta_contract = 无 CTA` 是**整份产出的边界，不只是 `cta_surface` 那一格**。
评论区是最容易破口的地方 —— 它看起来只是"互动"，不像"转化"。

**先看上游闭合了没有。** 本小节的「可以做」是 `cta_contract` **只禁止业务动作、
未给出闭合表达**时的空间。上游出现「只保留内容本身」「不做任何引导」这类闭合表达时，
按「CTA 权威顺序」第 1 条，评论区**同样不得**要求受众回答、留言或互动——
此时评论区只能写不指向受众动作的内容，或者不写。

**不得出现**：

- 「猜对有惊喜」「答对送」「抽奖」这类**奖励式互动**
- 「评论区领」「私信我领」「扣 1 发你」这类**领取动作**
- 「关注看答案」「下条揭晓」这类**用后续内容做交换**
- 到店、预约、购买、下单、加微信、咨询等**业务动作引导**
- 任何**未经授权的奖励与承诺** —— 包括说不清是什么的「有惊喜」

**可以做**：提一个能一句话回答的具体问题；把一个判断摊开让人接着问；
给一条诚实的「我答不出」。**这些都不需要挂奖励。**

> 为什么盯得这么紧：奖励式互动看着无害，但它**凭空创造了一个业务承诺**。
> 「猜对有惊喜」——惊喜是什么？谁发？发不发得出来？三个问题一个都答不上，
> 而观众已经当真了。这和无中生有报一个价格是同一类错误。

### 作者转发语

入口形态含**社交带出型**的平台上（哪些平台，查 `references/platforms.md` 第一节），**作者自己转发时说的那句话，比标题更早被读到**——它是内容进入熟人流的第一句。其余平台这一项可选。

写一句，规则同 PP-1：不是摘要，且不能承诺正文没有的东西。

## 发布前成片检查

五条，逐条看，不是流程：

1. **静音播放一遍**——看得懂吗？看不懂的话，在无声环境下刷到就是划走
2. **只看首帧 1 秒**——知道这是关于什么的吗？
3. **只看封面＋标题**——想点吗？是因为哪一句？
4. **看完之后**——我会存下来吗？存来干什么用？
   **答"不会"也是合格答案。** 有些内容天生不是收藏型（情绪、共鸣、一次性的场景）。这一条问的是"知不知道自己靠什么留存"，不是"必须能被收藏"——**不要为了让这一条通过而反向修改内容**。答"不会"时，第 5 条就是主判据。
5. **转发想象**——我会转给谁？转的时候我说一句什么？说不出来就不要指望转发
   **入口形态含社交带出型的平台上，这是主判据。** 转发一条给结论的内容，转发者背书的是一个**立场**（成本高）；转发一条没有结论的，背书的是一个**承认**（成本低，但暴露度高）。两者的转发驱动完全不同。

## 包装候选：数量由真实取舍决定

> 本节是 M4 新增，它替换源 Skill 输出块里「3 套路线」这个写死的数字。**PP-1 的标题候选规则不变**，本节与它同一原理。

**数量不固定。** 先问一句：这条内容的包装上，**存在真实取舍吗**？

- **存在真实取舍** → 给实质不同的路线。每条各自写明：**靠什么机制建立点击动机**、**什么条件下失效**。两条路线如果失效条件相同，它们是同一条。
- **不存在真实取舍** → **直接给推荐，路线数 = 1**。这不是缺陷，是判断做完了。**不机械凑数。**

**同义替换不构成新路线。** 换标题措辞、换一句开场、换语气、换修辞、换个案例、贴「情绪版／干货版」标签——发现即合并。这和 PP-1「同义替换不构成新的标题家族」是同一条判据在路线层的应用。

### 三层候选不得混写

```text
周期策略候选   —— 本周期做什么组合、目标如何分配、节奏如何安排   （持续运营层，本 Skill 不产出）
单条创意候选   —— 题材、钩子、叙事、表达机制                     （CS-1，本 Skill 不产出）
包装候选       —— 关键标题、封面、入口包装                       （本 Skill 产出）
```

- 三层**不得互相替代**，**不得混写进同一个候选列表**。
- 用户问「这条还能怎么做」时，属于哪一层就交给哪一层——**本 Skill 只在包装层给候选**。要改题材、钩子或叙事机制的，走 Return，不在包装层用换标题的方式假装解决。
- 用户可以选择、混搭、局部修改包装候选；**普通可逆的重出一版不新增确认闸。**

## Return 是闭环，不是一句建议

> 本节是 M4 新增。源 Skill 的 `return_to_script[]` / `return_to_production[]` 只写「回改建议」——一句建议没有处置、没有失效集，发出去就沉默丢失了。

### 每条 Return 七项，一项不少

| 项 | 写什么 | 写不好会怎样 |
|---|---|---|
| `source` | 哪个能力／哪个环节发出 | 上游不知道该谁看 |
| `highest_damaged_layer` | 被新事实实际破坏的**最上游**判断层 | 在下游打补丁，上游那个错还在 |
| `precise_gap` | 具体缺什么。**不写"信息不足"** | 收到的人不知道要补什么 |
| `affected_objects[]` | 受影响的对象逐个列出 | 影响面靠猜，要么多算要么少算 |
| `proposed_disposition` | 接受并局部修改 ｜ 依据权威/事实/边界拒绝 ｜ 精确升级 | 没有处置＝没有闭环 |
| `needs_user_decision` | true / false | 该交人的没交人，或不该交人的去打扰人 |
| `downstream_stale[]` | 哪些下游变 STALE，**只列真实依赖** | 全链失效（多算）或漏项（少算） |

**处置三选一，且只选一。** 拒绝也是合法处置，但**必须给出理由**——**不得沉默丢失**：一条 Return 既不接受也不拒绝地悬着，是最坏的一种。

**修复指向最高失效层。** 破的是正文语义就回 Creative Script，破的是覆盖就回 Production Director，**不在包装层打补丁**假装解决。

### Return 不自动回环

**收到 Return 不等于自动重跑上游。** 本 Skill 发出 Return 之后：

- 不假设上游会跑、不等待上游跑完、不代替上游跑；
- 已经能定稿的部分照常定稿，**只把依赖该 Return 的那一支挂起**；
- 恢复时**先查目标系统**，防止重复副作用（同一条内容不要被包装两遍、发布两遍）。

### 解析失败 ≠ NONE

上游给来的 Return 或兑现证据解析不了时，**置 `parse_status = PARSE_FAILED`，保留失败原文，局部阻断那一支**。

**不得**把解析失败伪装成空数组、`NONE` 或「无回改建议」——那会让下游读成"检查过了，没问题"，而实际是"根本没读懂"。这两件事的差别是本 Skill 里最贵的一个差别。

## 语义事实核验失败时怎么办

> 本节是 M4 新增。

**核验失败阻止交付。** `fact_check_status = FAIL` 时不出可发布的最终包，`mode` 不得因此被改写。

**保留原 Artifact 与失败输出。** 原来的完整产出留着，核验失败的那一条以及失败原文一起留着。

**不得删句翻绿。** —— **不得靠删掉被质疑的那句话，把结论从失败改成通过。** 那不是通过，那是把证据处理掉了。要通过只有两条路：补上真实的 `fact_id` 回指，或者由有权者依据权威/事实/边界作出裁决；**自己删一句让检查器不再报错，两条都不是。**

**只阻断依赖该事实的那一支。** 一条事实核验不过，不使整份包装作废：

- 不依赖它的标题、封面、文案、评论区设计 **照常完成**；
- 依赖但可以条件化的 → 条件化产出，写明成立条件；
- 依赖且产出即编造的那一支 → **暂停该支**。

**不降低其余部分的创意深度与成品质量。** 一处事实缺口不是把整条内容做浅的理由——阻止的是**无依据的具体主张**，不是这项任务本身。

**核验不重写创意。** 核验只回答"这句话有没有依据"，它**不负责**换一个标题、改一个钩子、调一次语气。核验失败之后的重写是包装判断，仍按 PP-1 至 PP-5 做，**不是由核验结论代做**。

## 事实来源必须蕴含该主张

> 本节是 b1 新增。它是 `used_fact_refs[]` 「找不到对应 `fact_id` 时，只有一条路：不生成它」
> 那一条的**判定细则**，不替代它，也不放宽它。

**什么算「真实行为主张」。** 产出里任何断言**具体人物、组织或品牌在过去或现在实际做过某件事**
的句子，都是真实行为主张。它包括但不限于：某人做过什么、说过什么、一直／长期／向来怎么做、
团队内部怎么决定的、店里／公司里历来的做法。
它**读起来像叙述**，不像"事实陈述"——这正是它最容易被漏掉的原因。

**回指必须是蕴含关系，不是相关关系。** 挂上一个 `fact_id` 不等于有来源。
判定只问一句：**这条来源自己有没有说这件事发生过？**

| 来源里写的 | 能不能推出「他实际长期用过这个方法」 |
|---|---|
| 他的职务、岗位、头衔 | **不能** |
| 他长期接触某类工作、某类人群、某类场景 | **不能** |
| 行业里一般都这么做 | **不能** |
| 这个方法本身是合理的、专业的 | **不能** |
| 来源逐字写了「他用这个方法」「他一直这么做」 | 能 |

**职责不蕴含行为。** 一个人负责某件事，不等于他用过某个具体方法；
接触过某类场景，不等于他形成过某套做法。**从职责推行为，是编造，不是推断。**

**任何限定语都不把无来源变成有来源。** 「这是推断」「基于职责的合理推断」「可能」「据说」
「印象中」「大概」「应该是」，以及正文之外的脚注、括注、说明行、免责句——
**一条都不改变这句话的性质**。读到它的人读到的仍然是一条关于真人的既成事实；
加一句说明不产生任何新证据，只是把问题连同一张便条一起交了出去。

> 这与「用户交付块的事实纪律」是同一条原理的两个面：
> 那一节讲的是**淘汰内容不许带着便条留下**，这一节讲的是**无来源主张不许带着推断标注留下**。
> 两种写法交出去的都是那句错的话。

**没有直接来源时，只有两个出口：**

1. **删除**该真实行为主张——依赖它的那一句、那一段、那一条预埋回答，一起拿掉；
2. **改为不主张真实历史的当前内容表达**——把方法、判断、框架写成**这条内容自己提出的**，
   不挂到任何真人的既往行为上。

这两个出口都不需要任何来源，因此**永远存在**，不构成阻塞。

**局部失效不升级为整任务拒绝。** 一处行为主张没有来源，只删除或改写**依赖它的那个局部分支**：
不依赖它的标题、封面、文案、平台适配、评论区设计**照常完成**；
其余部分的创意深度与成品质量**不降低**。
阻止的是**无依据的具体主张**，不是这项包装任务本身。
**因为一处事实缺口就交白卷、只交一句"资料不足"、或整体拒绝，都是错的。**

## 局部失效与不反向传播

> 本节是 M4 新增。

**包装自身的变化不反向使 Script、Brief 或 PD 失效。** 换了标题、调了封面文字层级、多出一个平台变体——上游一个字都不用改，**不得**因此让上游产物变 STALE。

**上游变化只使依赖部分失效**：

| 上游变了什么 | 失效的是 | 不失效的是 |
|---|---|---|
| 正文、内容承诺、`plan` 或 `manifest` 实质变化 | 依赖那部分的包装与可发布判断 | 不依赖它的路线、平台变体与评论区设计 |
| 平台变化 | 相关平台变体与发布条件 | 母版包 |
| CTA 权限变化 | `cta_surface`、相关平台变体与发布条件 | 标题、封面、正文文案（除非它们本身带 CTA） |

**「实质变化」指被下游实际消费的业务含义变了。** 排版、措辞、说明文字、重跑但结果未变、用户提过建议但最终没采纳——**都不触发失效**。

**判断不了影响关系的标 `STALE` 待定向复验。** 标 STALE 不算漏项；为了显得精确而假装知道依赖图才是错的。**多算**（让有证据、不受影响的项作废）和**少算**（漏掉已知依赖）**都是错**。

### 发布实例纪律

- 发布后再改，**必须形成新的内容版本**；
- **只有该新版本实际对外发布了，才形成新的发布实例**；
- **未再次发布的修订不得产生或冒充发布实例**；
- **不得改写旧的发布历史**——已发布内容及其发布实例保留为历史，不因上游后来变化而失效或被改写；
- 只有**实际发布过的那个准确版本**才能绑定真实效果数据。

## 用户交付块的事实纪律

用户交付块是**直接交到执行人手上**的那一页。它和完整 Artifact 的定位不一样：

| | 完整 Artifact | 用户交付块 |
|---|---|---|
| 给谁看 | 给核账的人 | 给拿着它去干活的人 |
| 能不能记问题 | **能** —— 淘汰了什么、为什么淘汰、哪条没依据，都该写清楚 | **不能** |

### 不可用的内容，必须真的拿掉

判断某句话不能用之后，**从用户交付块里删干净**，而不是留在那儿加一句说明。

用户交付块里**不得出现**下列任何一种写法：

- 「已删除」「已剔除」「已移除」
- 「审查发现」「审查时发现」「修正后」「修正为」
- 「原方案」「上一版」「之前的版本」
- 「未核实，不得使用」「这句话不能使用」
- 以及**任何被淘汰内容的全文**

**尤其不得把「错误内容」和「已删除说明」写在同一句话、同一个字段里。**
那不是删除，那是把问题连同一张便条一起交了出去 —— 执行人读到的仍然是那句错的话。

> ❌ 「作者回复时补充：试过完全解开但太松，没采用（此条已删除，因无事实支撑，改为不提）。」
> —— 编造的内容和「已删除」写在同一句里，一起交到了执行人手上。**这不叫删除。**
>
> ✅ 那一句从用户交付块里**完全不出现**；淘汰原因写在完整 Artifact 里。

### 自检和自述都不是完成证据

> **你在自检、`used_fact_refs[]` 或任何说明文字里声称「已删除」「已处理」「已核实」，
> 不构成完成证据。最终判定以用户交付块的实际文本、以及有效的 `fact_id` 对应关系为准。**

**不得用自我声明覆盖实际正文。** 说了删，正文里还在，那就是没删 —— 而且比不说更糟，
因为它会让下游以为这一处已经清理过了。

判断标准只有一个：**把你说删掉的那句话，回用户交付块里搜一遍。搜得到，就是没删。**

**（M4 补充）** 用户交付块里同样**不出现内部分级术语与内部状态码**：`PRE` / `MIXED` / `FINAL`、
`KNOWN_BUT_NOT_AUTHORIZED`、`PLATFORM_SPEC_UNVERIFIED`、`STALE`、Return 的七个字段名——
这些留在完整 Artifact 里。但**「不泄露」不是「少给」**：用户必须做的选择、包装成立的条件、
真实的阻断，一项都不能投影掉，只是要用自然语言说。

## 自检

1. 标题是摘要还是缺口？——摘要就重写
2. 候选覆盖了几种入口类型？——**只有一种等于只有一个候选**；类型数与候选数对得上吗
3. 封面和标题是不是在说同一件事？——是就浪费了一半
4. 刷到型平台的首帧和点击型平台的封面，是同一张吗？——是就说明没做平台适配
5. 平台改写里标了几项"不变"？——一项没有＝为改而改；全都不变＝没做适配
6. 发布文案开头三行单独拿出来，成立吗？
6b. **逐句比对发布文案正文和逐字稿**——有几句是口播稿的搬运？**一句都不该有**。自己声称"没有复述"不算数，要真的比对过
7. mode 是**按三级判据依次**推出来的，还是拍脑袋填的？判 FINAL 之前，`uncovered_beats[]` 里每一项**都写出已完成的处置结果**了吗——还剩一项 OPEN 就该是 MIXED。PRE／MIXED 里仍悬着的那部分产出，有没有全部标注为草案？
8. FINAL 模式下，`realized_payoff` 是从 **beat 级** manifest 归纳出来的，还是拿一句"拍了 42 分钟"当依据？
8b. `used_fact_refs[]` 里，`realized_payoff`／推荐标题／封面／发布文案／评论区事实陈述，
    **五处都回指到具体 `fact_id` 了吗**？有没有哪一句是事实性表达却挂不上任何 `fact_id`——
    挂不上就不能留在定稿里。
8c. `used_fact_refs[]` 里的编号，**每一个都是 `BRF-SUHE-001-XXX` 这样的登记全称**吗？
    有没有写成 `F02` 这种简写、或者一个 `fact_refs[]` 里根本没有的号？
    另外——产出里**每一处"某人做了某事／某人说了某句话／我们当时怎么决定的"**，
    都在表里挂上号了吗？漏的那几处，就是最可能编出来的那几处。
9. `explicit_non_promise[]` 里的东西，标题、封面、置顶评论有没有把它悄悄承诺回来？
9b. 上游 `constraints[]` 里的禁令，**封面和首帧的选帧**守住了吗？——第三方入镜、未成年人不露正脸这类禁令，最容易在封面上破功
10. 平台规格拿不到时，出的是**条件式改写**（分支型）与**定性制作要求**（数值型），
    还是白卷、或者一个自己编的数字？`platform_spec_status` 标了吗？
11. **（M4）** `evidence_basis` 写清楚了吗——本次兑现证据是哪一类、来源、确认状态、权限、时效？
    有没有把资产级数量（「拍了 42 分钟」「有 36 张图」）当成兑现证据用？
    有没有因为「按流程应该先有 `cs_final` / `pd_final`」就要求补跑 CS 或 PD？——**一次都不该有。**
12. **（M4）** `packaging_routes[]` 的条数，是**判出来**的还是**凑出来**的？
    任意两条的失效条件一样吗——一样就是同一条。
    列表里有没有混进周期策略候选或单条创意候选？
13. **（M4）** 每条 `return_to_script[]` / `return_to_production[]` 都写全七项了吗？
    `precise_gap` 有没有写成"信息不足"？`proposed_disposition` 是不是**只选了一个**？
    `downstream_stale[]` 有没有把不依赖的项也拉进来（多算）或漏掉已知依赖（少算）？
    上游给来的东西解析不了时，标的是 `PARSE_FAILED` 并留了原文，还是写成了空数组？
14. **（M4）** 事实核验失败时，原 Artifact 与失败输出都留着吗？
    有没有靠删掉被质疑的那句话把结论改成通过？——**把删掉的那句回失败清单里搜一遍。**
    不依赖该事实的那些部分，是照常完成的，还是被一起做浅了？
15. **（b1）** 产出里每一处「某人／某组织过去或现在实际做过某事」的主张，
    把它和它挂的来源**原文并排读一遍**——**这条来源自己说过这件事发生过吗？**
    只写了职务、岗位、长期接触某类工作，那就是**没有来源**。
    有没有哪一处是靠「这是推断」「基于职责」「可能」这类限定语留下来的？——**限定语不是来源。**
    没有来源的那几处，删掉了还是改成了不主张真实历史的表达？
    删改之后，不依赖它的部分是照常完成的，还是被一起做浅了？
16. **（b1）** 把 `cta_contract` 的**原文**抄到眼前，不看自己的复述——
    它有没有给出闭合表达（只保留内容本身／不做任何引导／不做关注评论收藏）？
    给出了的话，整份产出里还有没有任何一句在**要求受众做动作**：
    句末指向受众等一个回答、评论区设计、引导关注收藏转发点赞、参与话题？
    合规自检的每一行，对照的是原文全部，还是只挑了「不做购买引导」这半句？
    有没有自造一个「低风险互动」「温和引导」之类的类目把某一处放行？
