# 内容生产三份 Skill 验收标准 v1.0

**文件性质：** 强制性验收制度
**适用对象：** `Creative Script`、`Production Director`、`Publishing & Packaging`
**状态：** `NORMATIVE`
**对应构建规范：** 《内容生产三份 Skill 构建规范 v1.0》
**目的：** 建立统一、可重复、可追溯的三份 Skill 验收体系，防止“文档写得专业但没有真实提质”“单体优秀但端到端不可运行”“评分很高但存在致命缺陷”。

---

# 0. 验收结论定义

验收只允许输出以下状态：

| 状态                                        | 含义                                 |
| ----------------------------------------- | ---------------------------------- |
| `ACCEPTED_FOR_PRODUCTION`                 | 已达到生产使用标准                          |
| `ACCEPTED_WITH_NON_BLOCKING_IMPROVEMENTS` | 所有强制门已通过，但存在不阻塞生产的小项               |
| `REJECTED_NEEDS_REVISION`                 | 至少一项强制门失败                          |
| `HOLD_REQUIRED_EVIDENCE`                  | 关键测试条件、真实输入或环境证据不足，无法合法判定          |
| `MARKET_VALIDATED`                        | 在生产验收通过后，又取得发布后实验性市场证据；不得由离线测试直接获得 |

不得使用：

* 基本通过；
* 大体完成；
* 90%完成；
* 应该可以；
* Mostly Done。

---

# 1. 验收总原则

## 1.1 硬门优先于总分

任何 Hard Gate 失败：

> **总分再高也不得通过。**

---

## 1.2 效果优先于文档完整度

一份 Skill 即使：

* 文件结构完美；
* 写法专业；
* 评分表全部漂亮；

但在 Skill/No-Skill 对照中没有稳定产生质量增益，则判定 Skill 无效。

---

## 1.3 单体质量与系统质量分别验收

必须分别验收：

1. Creative Script；
2. Production Director；
3. Publishing & Packaging；
4. 三份 Skill 全链。

任何一项失败，整体系统不得进入 `ACCEPTED_FOR_PRODUCTION`。

---

## 1.4 离线验收不得冒充平台结果

离线测试可判断：

* 创意差异；
* 专业判断；
* 张力；
* 可信度；
* 人物自然度；
* 可拍性；
* 包装质量；
* 行动意愿。

不得声称已经证明：

* 爆款率；
* 真实完播提升；
* 真实互动提升；
* 真实转化提升；
* 算法必然青睐。

---

# 2. 总验收公式

最终通过必须满足：

```text
FINAL_ACCEPT =
    ALL_HARD_GATES_PASS
AND STRUCTURE_PASS
AND INSTRUCTION_QUALITY_PASS
AND PROFESSIONAL_SCORE_PASS
AND EFFECT_LIFT_PASS
AND GENERALIZATION_PASS
AND INTERFACE_PASS
AND PRODUCTION_RUNTIME_PASS
AND END_TO_END_PASS
```

同时满足：

* Creative Script ≥ 85/100；
* Production Director ≥ 85/100；
* Publishing & Packaging ≥ 85/100；
* 全链 ≥ 85/100；
* 关键能力归一化得分均 ≥ 80%；
* 每份 Skill 最终六任务盲测至少 4/6 优于 No-Skill；
* 三份 Skill 合计至少 13/18 优于 No-Skill；
* 不得存在实例污染；
* 不得出现伪完成；
* 不得输出空正文；
* 不得泄漏内部推理；
* 真实生产环境必须跑通。

# 3. Hard Gate：一票否决

以下全部必须通过。

| 编号        | Hard Gate             | 通过定义                                |
| --------- | --------------------- | ----------------------------------- |
| **HG-01** | 完整可运行                 | 有输入、判断过程、选择/深化、输出和返回逻辑              |
| **HG-02** | 正向能力占主体               | 主体在创造优秀内容，而非大篇幅审核、防错                |
| **HG-03** | 高差异候选                 | 有真实创意空间时能够生成不同 Creative Families    |
| **HG-04** | 选择与深化                 | 不只列方案；必须能够淘汰、选择、融合并深化               |
| **HG-05** | 知识正确分层                | 稳定能力、条件知识、动态平台知识和运行输入没有混写           |
| **HG-06** | 服务范围成立                | 在声明支持的行业、形式、素材、资源、主体和平台范围内不存在结构性失效  |
| **HG-07** | 无实例污染                 | 删除品牌、人物、SKU、案例原句后仍能运行               |
| **HG-08** | 职责边界正确                | Script、Director、Packaging 不互相重做核心职责 |
| **HG-09** | 多模态分工成立               | 语言、动作、画面、声音、字幕不是重复承担同一信息            |
| **HG-10** | Production Profile 生效 | 资源变化会实质改变方案                         |
| **HG-11** | 事实与创意同时成立             | 不把虚构经历、数据、效果、反馈写成事实                 |
| **HG-12** | 平台稳定/动态分离             | 当前热点、固定秒点和算法观察未写死到稳定内核              |
| **HG-13** | 输出为生产成品               | 不以“建议、分析、可考虑”代替当前职责的实际成品            |
| **HG-14** | 运行接口明确                | 输入、引用和输出结构可被生产环境直接调用                |
| **HG-15** | 无审查系统污染               | Skill 不生成无关的风险报告、治理报告、模型评分报告        |
| **HG-16** | 真实运行成立                | 不仅静态检查，至少完成规定模型实跑                   |
| **HG-17** | 无伪完成                  | 缺关键输入时明确 RETURN/HOLD，不声称已经完成        |
| **HG-18** | 无推理泄漏                 | 最终输出不得出现内部思维链、`<think>` 或等价内容       |

任何一项失败：

`REJECTED_NEEDS_REVISION`

# 4. Layer 0：结构与工程验收

本层检查 Skill 文件本身。

## S1. 名称

必须：

* 唯一；
* 可检索；
* 与职责一致；
* 符合当前 Skill 宿主的命名格式。

如采用当前项目的英文 Skill 目录约定，使用小写字母、数字和连字符。

---

## S2. Description

必须同时回答：

1. 它做什么；
2. 什么时候应调用；
3. 什么情况下不应调用或可以跳过。

---

## S3. 触发覆盖

针对典型用户表达测试触发，不得出现系统性：

* under-trigger；
* over-trigger。

---

## S4. 正文密度

`SKILL.md` 不得成为研究报告。

项目 v1 推荐控制在 500 行以内；超过时必须证明无法通过 `references/` 或 `scripts/` 拆分。

---

## S5. 引用结构

引用保持简单，不构造深层引用链。

---

## S6. 长参考可导航

长引用文件必须：

* 有标题；
* 有目录或清晰章节；
* 可按条件加载。

---

## S7. 路径一致

所有项目路径符合当前运行环境统一约定。

---

## S8. 术语统一

同一概念不得无理由混用多个名称。

例如不能同时把一个概念称为：

* Hook；
* 钩子；
* 抓手；
* 开场承诺；

却不给出明确区分。

**本项目已作出的区分裁决（验收按此判定 S8 是否通过）**：

| 概念 | 唯一正式字段 | 含义 |
| --- | --- | --- |
| 开场 | `opening` | 内容最先被用户感知的表达单元 |
| 开场承诺 | `opening_promise` | 开场向用户建立的、正文需要兑现的继续消费理由 |
| Hook / 钩子 / 抓手 | —— | 仅为行业通俗叫法，不得作为正式字段名 |
| 创意家族 | `creative_family` | 满足三项差异判据的不同内容结构方向 |
| 创意变体 | `creative_variant` | 同一家族内不改变核心结构的表达差异 |
| 标题家族 | `title_family` | 同一条内容的多个标题入口，**与 `creative_family` 不是同一概念** |

同一概念在不同作用域重名时（如 `HOLD`），必须由字段名限定，不得裸用。

---

## S9. 时效知识隔离

平台规则、趋势、算法观察、工具能力不得散落在稳定 Skill 主体。

---

## S10. 自由度匹配

不得将高自由度内容创作写成僵化步骤模板。

### Layer 0 门槛

**S1—S10 全部通过。**

不过则停止，不进入效果验收。

---

# 5. Layer 1：指令质量验收

## W1. 可执行性

随机抽取 10 条核心指令。

要求：

> 一个不知道作者原意的执行者能够据此明确知道下一步做什么。

合格线：

**≥9/10。**

“有质感”“更自然”“加强共鸣”等形容词不能单独作为指令。

---

## W2. 可判定性

所有：

* Hard Rule；
* 自检项；
* 返回条件；

必须可被第三方判断。

合格线：

* 自检项 100% 可判定；
* 主要硬约束 ≥80% 可判定。

---

## W3. 理由充分性

重要硬约束必须说明其专业原因。

合格线：

**≥80% 的关键硬规则存在明确理由或机制解释。**

---

## W4. 禁止项针对性

禁止项必须满足至少一项：

* 针对实际 baseline 常见错误；
* 保护上游合同；
* 保护事实真实性；
* 保护资源可执行性；
* 保护跨 Skill 职责边界。

纯粹为了显得严谨而增加的禁令应删除。

---

## W5. 非通用性

逐条判断核心能力是否为无 Skill 模型已经稳定具备的常识。

如核心正文超过 **40%** 只是 baseline 已稳定具备的内容，则必须压缩或重构。

最终以 Layer 3 的 Skill/No-Skill 实测为准。

---

## W6. 不过拟合

删除所有示例后：

**≥90% 的核心规则仍然可执行。**

---

## W7. 示例质量

示例必须：

* 明确标为“例”；
* 展示具体输入/判断/输出；
* 不得成为唯一合法答案。

---

## W8. 多选项有决策依据

给出多个方法时，必须：

* 指定默认值；或
* 给出何时选 A、何时选 B 的明确判据。

---

## W9. 密度

随机抽 20 句核心正文。

可以删除且不会造成信息损失的句子：

**≤2/20。**

---

## W10. 冲突裁决

至少测试以下类别：

* 自然表达 vs 信息精确；
* 创意强度 vs 事实边界；
* 视觉创意 vs Production Profile；
* 平台适配 vs 人格一致；
* 包装吸引力 vs 正文兑现；
* 高资源理想方案 vs 低资源真实执行。

必须能够稳定裁决。

---

## W11. 无审核系统污染

本标准**不采用“某些词出现次数必须为0”**的旧做法。

真正检查：

> 与内容生产无关的审核、风险、治理内容是否占据了 Skill 专业注意力。

真实性、权属、承诺兑现和事实边界属于内容质量和生产合同，不得因避免“审核感”而删除。

### Layer 1 门槛

W1—W11 全部达到标准。

| ------------------------ | ------: | ----------------------------------------- |
| Brief理解与 Audience Change |       8 | 正确继承任务、用户、人物和责任；明确观众变化                    |

| 开场与 Promise 兑现          |      10 | 第一感知单元建立明确理由；正文真实兑现                       |
| Narrative Engine 与状态变化   |      14 | 有明确推进动力；主要段落产生状态变化；转折不是硬造                 |
| 人物、关系与真实口语               |      13 | 人物资格、动机、关系姿态和人格可辨；非职业人物能自然表达              |

| 记忆与传播                    |       6 | 存在可记忆单位；内容可被用户复述                          |

| 选择、融合与深化                 |       8 | 能淘汰、选择、解释原因、吸收局部优势并形成完整成品                 |
| **总计**                   | **100** |                                           |

### 关键能力

以下归一化得分不得低于 80%：

* Creative Concept 与家族分化；
* Narrative Engine；
* 人物、关系与真实口语。

### Creative Family 最低判据

两个方向必须在以下五项中至少三项不同：

* 核心问题/矛盾；
* Narrative Engine；
* 人物角色/关系；
* 信息顺序；
* 视觉前提/最终回报。

**创意变体不计入家族数量。** 只改变开场、进入角度、语气、修辞、标题或案例的方案属于
`creative_variant`，不满足上述三项差异判据，不得用于证明已生成多个实质不同方向。

默认生成 **4 个** Creative Families；因任务复杂度低、合法候选空间有限或方向已高度冻结
而减少时，最少 2 个，且必须写明减少理由。

不得低于80%：

* 视觉转译；
* 镜头功能；
* 表演与剪辑。

### 镜头最低判据

每个关键镜头至少承担一项：

* 事实证据；
* 展示变化；
* 建立人物关系；
* 建立预期；
* 制造或释放张力；
* 人物反应；
* 时间、空间或情绪转场。

无法说明功能的镜头应删除。

具体平台阈值和秒点以带日期参考为准。

# 8. 全链严重错误：直接失败

以下任一出现，全链直接 FAIL：

* Production Director 重选内容主题；
* Packaging 为标题创造正文不存在的结论；
* Script 无视 Production Profile 输出不可执行方案；
* 下游缺关键输入却自行补写事实；
* 三份 Skill 大量重复同一职责；
* 平台适配破坏已确认内容核心；
* Promise 在链路中逐级放大；
* 人物人格在下游完全丢失；
* Evidence 在下游被替换成无法证明的表达。

---

# 9. Layer 3A：Skill / No-Skill 效果验证

这是验收的决定性实验。

---

## 9.1 Pilot Lift Test

每份 Skill 先使用四个不同任务：

```text
同一模型
同一输入
同一任务
A = 不使用 Skill
B = 使用 Skill
匿名盲评
```

合格线：

**≥3/4 选择带 Skill 输出。**

且评审者必须说明具体好在哪里。

若无法说明差异：

该次不计有效胜利。

---

## 9.2 Final Lift Test

通过 Pilot 后，每份 Skill使用六个跨上下文任务。

合格线：

* 每份 Skill ≥4/6 优于 No-Skill；
* 三份 Skill 总计 ≥13/18 优于 No-Skill。

若出现一次**明显严重退化**，即使总胜率通过，也必须定位造成退化的规则并修订后重测。

---

# 10. Layer 3B：判据区分力

对用于判断好坏的验收标准，同时测试 baseline。

如果 baseline 几乎总能通过某条判据：

该判据不能证明 Skill 增益。

合格线：

**有真实区分力的判据 ≥70%。**

---

# 11. Layer 3C：指令遵循

检查实际输出是否执行 Skill 的关键决策，而非只模仿格式。

合格线：

**≥8/10 核心行为被真正执行。**

未执行项必须逐条记录。

---

# 12. Layer 3D：生产具体化

当前 Skill 输出必须能够直接进入其下一执行环节。

不得以以下表达替代实际方案：

* 建议；
* 可以考虑；
* 视情况；
* 适当；
* 酌情；
* 后续再优化。

存在不确定条件时，应提供：

* 选择依据；
* 默认行为；
* Return/Hold 路径。

---

# 13. Layer 3E：否决能力

如果 Skill 输出失败候选或淘汰理由：

**≥80% 必须是机制性原因。**

合格：

> 该方向要求同时解释六个卖点，会把原本替用户做选择的任务重新变成信息堆积。

不合格：

> 不够吸引人。

---

# 14. Layer 3F：多模型一致性

至少测试：

1. 当前生产目标模型；
2. 两个不同模型家族的参考模型。

要求：

* 核心输出合同完整；
* 关键字段不丢失；
* 不发生某模型直接跑偏；
* 质量允许存在差异。

如果当前生产环境为 `Dify + Qwen`：

> **Qwen 为强制测试模型。**

参考模型版本必须在测试记录中冻结，不得测试期间中途更换。

> **当前状态**：`production_model_status: PRODUCTION_MODEL_UNCONFIRMED`。
> 目标生产模型尚未由 Founder 冻结，本条中的模型名以冻结结果为准；
> 冻结前不得据此认定某一模型已被选定。

---

# 15. Layer 3G：成本

记录：

* baseline token；
* with-Skill token；
* baseline 延迟；
* with-Skill 延迟；
* Lift 结果。

不规定单一成本阈值。

但如果成本显著增加而 Lift 只勉强达到最低线：

必须回到构建规范进行精简。

---

# 16. Layer 3H：泛化覆盖

验收至少覆盖以下六轴：

| 轴              | 必须覆盖的差异          |
| -------------- | ---------------- |
| Subject Domain | 至少覆盖明显不同的商业/内容领域 |
| Delivery Form  | 口播、图文、演示、对话/采访等  |
| Content Origin | 新拍、已有素材、评论/访谈等   |
| Resource Tier  | 单人低资源、小团队、高资源    |
| Service Object | 个人、企业、多品牌或IP类主体  |
| Platform       | 当前声明支持的平台        |

不得使用完整笛卡尔积穷举。

采用：

> **文本硬编码扫描 + 每轴两端/中间抽样 + 高风险组合测试。**

---

# 17. C1：无硬编码假设

Skill 核心不得隐含假设：

* 一定有视频；
* 一定能新拍；
* 一定有实体商品；
* 一定有真人；
* 一定有团队；
* 一定有门店；
* 一定是企业；
* 一定有历史内容；
* 一定有某个平台。

合格线：

**0 个会使声明支持范围失效的硬编码假设。**

---

# 18. C2：每轴抽样

每个覆盖轴至少取：

* 一个低资源/边界值；
* 一个典型值；
* 一个显著不同值。

验证：

> 方法是否改变，而专业质量是否仍成立。

图文不能只是“视频脚本改名字”。

已有素材任务不能默认要求重新拍摄。

低资源版不能只是“少拍几个镜头”。

---

# 19. C3：接口完整性

三份 Skill 字段合同必须满足：

### 孤儿字段

上游产生、下游永远不用：

**0 个无目的必需字段。**

### 缺口字段

下游必须使用、上游却不产生：

**0 个。**

### 缺失处理

每个 Required Input 缺失时：

**100% 有 Return/Hold/Degrade 路径。**

---

# 20. C4：扩展兼容

模拟至少三种变化：

1. 新行业；
2. 新平台；
3. 上游任务入口改变。

至少两种变化应当：

> 不修改 Skill 稳定核心，只通过运行输入或参考层适配。

否则说明专业能力被具体场景写死。

---

# 21. Layer 4：真实生产环境验收

---

## D1. 生产运行

在实际目标环境完整运行。

当前环境如为：

`Dify + Qwen`

则必须在该环境真实运行一次以上。

> **当前状态**：`production_model_status: PRODUCTION_MODEL_UNCONFIRMED`。
> 目标生产模型冻结后，本条按冻结结果执行；冻结前不得据此认定某一模型已被选定。

要求：

* 结构不塌；
* 字段完整；
* 无推理泄漏；
* 无伪完成。

---

## D2. 三份 Skill 端到端

至少完成一次：

```text
Creative Script
→ Production Director
→ Publishing & Packaging
```

要求：

> 上一份 Skill 的输出可以被下一份直接消费，不需要人工重写格式或解释语义。

---

## D3. 跳过路径

同时测试至少一个合法的非全链任务，例如：

* 已有成片只做 Packaging；
* 已有素材进入 Production/Edit；
* 图文任务不需要完整视频 Production。

跳过 Skill 的前提：

其负责的判断已经存在且仍有效。

---

## D4. 返回路径

至少测试：

* 事实不足；
* 关键镜头不足；
* 资源降级；
* 包装过度承诺；

能否返回正确角色。

---

## D5. 版本追溯

每份 Skill 必须记录：

* version；
* 修改内容；
* 修改原因；
* 触发修改的测试；
* 测试版本；
* 重新验收结果。

## 归因规则

### 只修改标题/封面

只能归因 Packaging 变量。

### 同时改变脚本、制作和包装

只能评价整个内容生产链。

不得把结果自动归因给其中某一份 Skill。

### 自然流量单条爆款

属于观察证据。

不得直接升级为通用规则。

# 27. 明确废弃的旧验收方法

以下不得作为最终通用验收标准：

* 只靠模型自述“这条规则我本来会不会”判非通用；
* 只做静态文档检查；
* 只看总分；
* 只看一条成功案例；
* 用自然流量爆款证明 Skill 因果有效；
* 强制所有任务完整经过三份 Skill。

# 28. 最终原则

本验收体系最终只回答一个问题：

> **这三份 Skill 是否能够在真实约束下，稳定地让模型产生比无 Skill 更专业、更有创意差异、更可生产、更可兑现，并能够完整串联为内容产品的输出。**

只有答案被结构检查、专业评分、盲测、泛化测试和真实生产运行共同证明为“是”，方可进入生产。
