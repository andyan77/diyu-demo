## 2. 关键编译决策

| 命题 | 编译结果 |
|---|---|
| M3 物理身份 | 冻结一份独立专业 Skill 源；Dify 节点/适配层拓扑留给工程 |
| 四类模式 | 作为同一 Skill 的四类业务行为，不做四份 Skill/四个用户模式 |
| 账号阶段 | 保留合同名称；拆开成熟度、临时覆盖、动作与健康假设 |
| “打法” | 证据成熟度与当前使用决定分开；不冻结数据库枚举 |
| 稳定/探索 | 动态取舍，无固定比例，合法时任一侧可暂为零 |
| 服装逻辑 | 条件加载附件；采用声明特定证据和局部失效 |
| 市场机会 | 信号+适配+供给/路径+窗口+可逆验证；不等同热点或同质化防守 |
| 六 Skill | 继承适用专业方法，不强制调用全部物理组件 |
| M3→Brief | 统一业务语义；包含内容本体，不含创意、脚本、拍摄和包装 |
| 用户参与 | 日常运营不动辄 Founder 审核；只上推真实权威域事项 |
| 验收 | M3 模块、M5 成品增益、真实运营、经营提升四层分开 |
